# Report Hub 의견 게시판 QA 및 Luna 구현 명세

## 1. 문서 목적

이 문서는 Luna 모델이 현재 공개된 Report Hub 의견 게시판을 안전하게 개선할 수 있도록 만든 실행 명세다.

- 공개 게시판: `https://aireport.ai-hub-os.com/board/`
- GitHub Pages: `https://aihubos.github.io/reportmode/board/`
- 저장소: `/Users/JeremyLee/Projects/reportmode`
- 기준 브랜치: 구현 시점의 최신 `origin/main`
- 기술: 정적 HTML/CSS/JavaScript + Cloudflare Worker + D1

현재 공개 기능은 정상이다. 글과 댓글의 작성·조회·수정·삭제, 관리자 이름 보호, 비밀번호 확인, 조회수 중복 방지가 동작한다. 이번 후속 작업은 기능 재작성보다 UX 완성도와 상태 전달을 높이는 작업이다.

## 2. 반드시 지킬 작업 원칙

1. 기존 로컬 작업 폴더가 더러우면 직접 수정하지 않는다.
2. 최신 `origin/main`에서 clean worktree와 `codex/` 브랜치를 만든다.
3. 기존 `/comments`, `/requests`, 비공개 보고서, 관리자 기능은 수정하지 않는다.
4. 게시판 사용자 입력은 계속 `textContent`로 출력한다. 사용자 글을 `innerHTML`에 넣지 않는다.
5. 관리자 비밀번호를 HTML·CSS·JavaScript에 작성하지 않는다.
6. 게시판 화면은 아래 공통 소스를 수정하고 빌드로 생성한다.
   - `src/site/board/index.html`
   - `src/site/assets/community-board.css`
   - `src/site/assets/community-board.js`
   - 생성 파일: `board/index.html`, `assets/community-board.css`, `assets/community-board.js`
7. 메인 상단 버튼은 `src/lib/render.ts`와 `src/styles/magazine.css`를 수정한 뒤 `archive/index.html`을 다시 생성한다.
8. 보고서마다 HTML을 직접 고치지 않는다. 공통 브랜드 자산을 사용한다.

## 4. 우선순위별 수정 명세

### P0-1. 모바일 글쓰기 CTA를 한 개만 노출한다

현재 모바일에는 상단 `+` 버튼, 소개 카드의 `새 글 작성`, 우측 하단 `글쓰기`가 동시에 보인다. 한 화면에 같은 기능이 세 번 반복되어 시선이 분산된다.

구현:

1. 700px 이하에서는 `.community-board-intro-write`를 숨긴다.
2. 모바일 기본 CTA는 `.community-board-mobile-write` 하나로 통일한다.
3. 상단 `.community-board-top-write`는 아이콘형 보조 진입점으로 유지해도 되지만, 하단 버튼과 dialog가 열려 있을 때는 숨긴다.
4. `dialog[open]` 상태에서는 `.community-board-mobile-write`를 `display:none` 처리한다.
5. 상세 화면에서도 댓글 등록 버튼과 겹치지 않도록 하단 고정 버튼을 숨기거나 상세 화면에서는 `글쓰기` 대신 목록 화면에만 표시한다.

완료 조건:

- 390px 목록 화면에서 글쓰기 CTA가 최대 2개, 권장 1개만 보인다.
- dialog가 열리면 배경의 고정 글쓰기 버튼이 보이지 않는다.
- 상세 댓글 등록 버튼과 고정 글쓰기 버튼이 겹치지 않는다.

### P0-2. 모바일 dialog의 키보드·스크롤·저장 버튼을 안정화한다

현재 dialog는 화면에 맞지만 iPhone 키보드가 열리면 하단 `취소/게시하기`가 가려질 가능성이 있다.

구현:

1. `.community-board-dialog`에 `max-height: calc(100dvh - 20px)`를 유지한다.
2. dialog 내부 form을 `grid-template-rows: auto minmax(0, 1fr) auto`로 나누거나 본문 영역에 `overflow-y:auto`를 적용한다.
3. `.community-board-dialog-actions`는 dialog 하단에 `position:sticky; bottom:0`으로 둔다.
4. sticky 영역 배경은 흰색, 상단 1px 구분선, `padding-bottom: env(safe-area-inset-bottom)`을 적용한다.
5. 입력 오류가 있으면 첫 오류 필드에 `aria-invalid="true"`, 오류 문구와 `aria-describedby`를 연결한다.
6. 저장 성공 또는 취소 시 비밀번호와 본문 임시값을 비운다.

완료 조건:

- 390×844에서 모든 필드와 저장 버튼에 도달한다.
- iOS 키보드가 열린 상태를 모사해도 저장 버튼이 접근 가능하다.
- Escape와 닫기 버튼으로 닫히며 원래 트리거로 포커스가 돌아간다.

### P0-3. 모든 저장·수정·삭제 결과를 공통 토스트로 알린다

현재 상태 문구가 폼 안쪽에만 있어 삭제·복사·수정 완료가 화면 위치에 따라 잘 안 보인다.

구현:

1. `src/site/board/index.html`의 `<main>` 직후에 다음 영역을 한 번만 둔다.
   - `id="board-toast"`
   - `role="status"`
   - `aria-live="polite"`
   - `aria-atomic="true"`
2. `showToast(message, type)` 공통 함수를 만든다.
3. 다음 이벤트에서 토스트를 표시한다.
   - 글 등록 완료
   - 글 수정 완료
   - 글 삭제 완료
   - 댓글 등록·수정·삭제 완료
   - 링크 복사 완료
4. 성공 토스트는 3초 후 닫고, 오류 토스트는 사용자가 닫거나 6초 후 닫는다.
5. 저장 중에는 중복 클릭을 막고 버튼 문구를 `등록 중`, `수정 중`, `삭제 중`으로 바꾼다.

완료 조건:

- 화면 어느 위치에서도 완료 결과를 즉시 인지한다.
- 스크린리더에도 상태 변경이 한 번만 전달된다.
- 연속 클릭으로 게시글이나 댓글이 중복 생성되지 않는다.

### P0-4. 삭제 확인에서 대상 정보를 명확히 보여준다

현재 삭제 dialog는 비밀번호만 요구해 사용자가 어떤 글 또는 댓글을 지우는지 확인하기 어렵다.

구현:

1. 게시글 삭제 dialog에는 제목을 최대 두 줄로 표시한다.
2. 댓글 삭제 dialog에는 댓글 본문 앞 80자를 표시한다.
3. 설명 문구는 다음으로 통일한다.
   - 글: `이 게시글과 연결된 댓글이 함께 삭제됩니다.`
   - 댓글: `이 댓글을 삭제하면 되돌릴 수 없습니다.`
4. 최종 버튼은 일반 파란색이 아닌 절제된 위험색 테두리 버튼을 사용한다.
5. 비밀번호 오류는 입력칸 아래에 표시하고 입력칸에 포커스를 유지한다.

완료 조건:

- 사용자가 삭제 대상을 dialog 안에서 확인할 수 있다.
- 잘못된 비밀번호 뒤에도 dialog가 닫히지 않는다.

### P1-1. 상세 화면의 빈 여백과 댓글 영역을 압축한다

짧은 게시글에서 본문 최소 높이가 크게 잡혀 댓글 입력까지 불필요한 빈 공간이 생긴다.

구현:

1. `.community-board-detail-content`의 `min-height:120px`를 제거하거나 48px로 낮춘다.
2. 본문 하단 padding을 데스크톱 28px, 모바일 22px 수준으로 줄인다.
3. 댓글 0개일 때 빈 상태 높이를 180px에서 88~110px로 줄인다.
4. 댓글 작성 폼과 빈 상태가 중복으로 큰 박스를 만들지 않도록 간격을 14~18px 범위로 통일한다.

완료 조건:

- 390px 상세 화면에서 제목·본문·댓글 입력 시작점이 과도하게 떨어지지 않는다.
- 긴 글은 기존 줄바꿈과 읽기 폭을 유지한다.

### P1-2. 모바일 목록 메타데이터의 읽기 순서를 정리한다

현재 작성자·관리자 배지·날짜·댓글·조회가 여러 행으로 흩어져 한 번에 읽기 어렵다.

구현:

1. 모바일 행은 다음 3단 구조로 정리한다.
   - 1행: 제목
   - 2행: 본문 미리보기 한 줄
   - 3행: 작성자·관리자 배지·날짜 · 오른쪽 댓글/조회
2. 댓글과 조회는 `댓글 0 · 조회 2`처럼 한 묶음으로 표시한다.
3. 카테고리는 모바일에서도 제목 위 작은 파란 텍스트 또는 pill로 표시한다.
4. 행 전체 터치 영역은 최소 76px 이상 유지한다.

완료 조건:

- 390px에서 한 게시글의 소유자, 분류, 날짜, 반응 수가 한 시선에 들어온다.
- 긴 사용자명과 긴 제목에서도 가로 스크롤이 생기지 않는다.

### P1-3. 게시판 첫 방문 안내를 실제 행동 중심으로 바꾼다

오른쪽 안내는 규칙 중심이고, 처음 온 사용자가 무엇을 써야 할지는 약하다.

구현:

1. 안내 제목 아래 첫 문장을 `보고서를 읽고 든 생각이나 AI 질문을 남겨 주세요.`로 추가한다.
2. 규칙은 짧게 유지한다.
   - 개인정보 작성 금지
   - 광고·도배 삭제 가능
   - 비밀번호 분실 시 직접 수정·삭제 불가
3. 비밀번호는 서버에 원문으로 공개되지 않고 수정·삭제 확인용이라는 짧은 설명을 폼 근처에 제공한다. 구현 사실과 일치하지 않는 보안 표현은 쓰지 않는다.

완료 조건:

- 처음 온 사용자가 글의 성격과 비밀번호 용도를 즉시 이해한다.

### P1-4. URL 상태와 뒤로가기를 자동 테스트에 추가한다

현재 상세 주소와 뒤로가기는 정상이나 회귀 방지 테스트가 더 필요하다.

구현:

1. `assets/community-board.test.mjs`에 다음 정적 계약을 추가한다.
   - `history.pushState`
   - `popstate`
   - `?post=` 처리
   - 사용자 본문 `textContent`
2. 가능하면 브라우저 테스트에 다음 흐름을 추가한다.
   - 목록 필터 선택
   - 상세 진입
   - 브라우저 뒤로가기
   - 필터와 검색어 복원
3. 상세 링크를 새 탭에서 직접 열어도 정상 표시되는지 확인한다.

완료 조건:

- 뒤로가기 후 목록 조건과 스크롤 위치가 자연스럽게 복원된다.
- 새로고침 후에도 같은 상세 글이 열린다.

### P2-1. 필터·검색·정렬을 더 단순하게 정렬한다

데스크톱에서는 검색창이 위, 카테고리와 정렬이 아래라 조작 영역이 두 줄로 분리된다.

구현:

1. 1024px 이상에서는 `카테고리 | 검색 | 정렬`을 하나의 툴바 안에 둔다.
2. 검색 입력 폭은 280~360px, 정렬은 110px 정도로 고정한다.
3. 검색어가 있을 때 `검색 초기화` 버튼을 제공한다.
4. 결과 수는 제목 아래가 아니라 필터 우측 또는 목록 헤더 가까이에 표시한다.

완료 조건:

- 사용자가 한 영역에서 필터·검색·정렬을 모두 찾는다.
- 모바일에서는 현재처럼 두 줄 이상으로 자연스럽게 재배치한다.

### P2-2. 관리자 작성 표시의 의미를 보완한다

관리자 배지는 보이지만 관리자가 왜 작성했는지, 답변인지 공지인지 구분되지 않는다.

구현:

1. 관리자 새 글의 카테고리는 기존 4개를 유지한다.
2. 관리자 배지에 `title="Report Hub 관리자"`를 추가한다.
3. 관리자 답글 기능을 추가하지 않는다면 임의의 중첩 답글 구조를 만들지 않는다.
4. 향후 공지 기능이 필요할 때만 별도 `공지` 타입을 데이터베이스 마이그레이션으로 추가한다.

완료 조건:

- 일반 사용자가 관리자 이름 사칭과 실제 관리자 글을 구분한다.

## 6. Luna 구현 순서

1. 최신 `origin/main`에서 clean worktree 생성
2. 현재 QA 문서와 게시판 소스 3개 확인
3. P0-1부터 P0-4까지 한 항목씩 구현
4. 각 항목마다 `npm test`, `npm run typecheck`, `git diff --check` 실행
5. P1 항목 구현
6. `npm run report -- archive-build` 실행
7. 생성 파일과 소스 파일이 동일한지 확인
8. 데스크톱 1440px, 태블릿 768px, 모바일 390px 화면 검수
9. 실제 글·댓글 CRUD 테스트 후 테스트 데이터 삭제
10. PR 생성·병합
11. Pages 빌드가 병합 SHA로 `built`인지 확인
12. 두 공개 주소에서 콘솔 오류·가로 넘침·글쓰기·댓글 흐름 최종 확인

## 7. 필수 자동 검증

```bash
npm run typecheck
npm test
npm run reports:integrity
git diff --check
```

`reports:brand-qa`가 기존 특정 보고서 문제로 실패할 경우, 이번 변경으로 새 실패가 생겼는지 분리해서 기록한다. 관련 없는 보고서 본문을 함께 수정하지 않는다.

## 8. 화면 검수 체크리스트

### 1440px

- 상단 게시판·AI Builders Lab 카드가 같은 142×48px
- 게시판 검색·필터·정렬 정렬
- 긴 제목 두 줄 제한
- 상세 본문과 댓글 사이 과도한 빈 공간 없음

### 768px

- 안내 카드가 목록 아래로 이동
- 검색과 정렬이 겹치지 않음
- dialog가 화면 밖으로 나가지 않음

### 390px

- 가로 스크롤 없음
- 글쓰기 CTA 중복 없음
- dialog 열림 중 배경 고정 CTA 숨김
- 키보드가 열려도 저장 버튼 접근 가능
- 댓글 등록 버튼과 고정 버튼이 겹치지 않음
- 모든 터치 영역 최소 44px
