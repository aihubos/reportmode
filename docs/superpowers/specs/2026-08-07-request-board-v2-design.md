# Report Wishlist v2 설계

## 목표

메인 페이지 우측의 `다음 리포트, 무엇이 궁금하신가요?` 패널을 신청자 정보와 관리자 답글을 함께 보여주는 공개 요청 게시판으로 확장한다. 로그인 없이 작성할 수 있고, 작성자는 설정한 비밀번호로 자신의 글을 수정하거나 삭제한다.

## 화면 구조

- 제목에는 노란색 형광펜 밑줄 효과를 적용해 시선을 모은다.
- 작성 폼은 `신청자 이름`, `수정·삭제 비밀번호`, `궁금한 내용` 순서로 배치한다.
- 게시물 카드는 신청자 이름 배지, 작성일, 본문, 수정·삭제 버튼 순서로 표시한다.
- 관리자 답글은 게시물 아래에 `관리자 답변` 표식과 함께 분리된 영역으로 공개한다.
- 관리자 답글이 없는 글에는 관리자 답글 작성 버튼을 제공한다.
- 데스크톱에서는 현재 우측 고정 패널을 유지하고, 모바일에서는 일반 흐름의 전체 폭 카드로 전환한다.

## 기능 흐름

### 신청자

1. 이름, 비밀번호, 내용을 입력해 요청을 등록한다.
2. 수정 버튼을 누르면 현재 내용을 편집할 수 있다.
3. 저장 시 작성 비밀번호를 서버에서 확인한다.
4. 삭제 버튼을 누르면 작성 비밀번호를 확인한 뒤 삭제한다.

### 관리자

1. 관리자 답글 버튼을 눌러 답변 입력 영역을 연다.
2. 관리자 비밀번호와 답변을 입력한다.
3. 서버가 관리자 비밀번호를 확인한 뒤 답글을 저장한다.
4. 관리자 답글은 모든 방문자에게 공개된다.

## 데이터와 API

- 기존 요청 데이터에 신청자 이름, 작성 비밀번호용 salt/hash, 수정 시각을 추가한다.
- 관리자 답글은 요청 ID에 연결된 별도 데이터로 저장한다.
- API는 요청 등록, 목록 조회, 작성자 수정, 작성자 삭제, 관리자 답글 등록을 제공한다.
- 기존 요청 글은 이름을 `익명`으로 표시하고 수정·삭제 비밀번호가 없으므로 읽기 전용으로 유지한다.

## 비밀번호 처리

- 신청자 비밀번호는 원문을 저장하지 않고 기존 댓글 방식과 동일하게 서버에서 변환해 저장한다.
- 관리자 비밀번호는 공개 HTML·JavaScript·Git 기록에 넣지 않고 Cloudflare Worker 비밀 환경값으로만 설정한다.
- 잘못된 비밀번호에는 기능별로 이해하기 쉬운 안내를 표시한다.

## 오류와 상태

- 입력 누락, 짧은 비밀번호, 서버 오류를 입력 폼 아래에 표시한다.
- 등록·수정·삭제·답글 저장 중에는 해당 버튼을 잠시 비활성화한다.
- 목록 로딩 실패 시 재시도 안내를 보여주되 작성 폼은 계속 사용할 수 있게 한다.

## 검수 기준

- 1440px에서 우측 고정 패널이 본문을 가리지 않고 스크롤을 따라간다.
- 390px에서 입력 폼, 게시물 본문, 버튼, 관리자 답글이 잘리지 않는다.
- 신청 등록 → 수정 → 관리자 답글 → 삭제가 실제 공개 API에서 순서대로 동작한다.
- 잘못된 신청자·관리자 비밀번호로는 수정·삭제·답글 등록이 되지 않는다.
- 테스트 데이터는 검수 후 모두 삭제하고 GitHub Pages의 최신 커밋 반영을 확인한다.
