# Report Hub 비공개 보고서 보관함 설계

## 1. 목표

Report Hub 도서관에 `비공개` 카테고리를 추가한다. 비공개 보고서의 제목, 썸네일, 본문은 관리자 인증 전에는 브라우저로 전송하지 않는다. 사용자가 비공개 보고서 주소를 직접 알아도 인증 전에는 본문을 열 수 없어야 한다.

기존 공개 보고서, Draft, 조회수, 댓글, 추천글, 숨김 보고서 기능은 그대로 유지한다.

## 2. 채택 구조

비공개 HTML과 썸네일은 Cloudflare R2 비공개 버킷에 저장한다. 목록과 운영 정보, 임시 인증 세션, 로그인 실패 제한 정보는 기존 Cloudflare D1에 저장한다. GitHub Pages에는 잠금 화면과 뷰어 껍데기만 배포하고 비공개 원문이나 메타데이터는 넣지 않는다.

다음 대안은 사용하지 않는다.

- CSS나 JavaScript로 공개 HTML을 숨기는 방식: 주소나 페이지 소스를 알면 원문이 노출된다.
- 공개 저장소에 암호화 파일을 두는 방식: 키 교체, 복구, 버전 관리가 복잡하고 운영 실수 가능성이 높다.

## 3. 사용자 흐름

### 도서관

1. 기존 카테고리 목록에 자물쇠 아이콘과 `비공개` 버튼을 표시한다.
2. 인증 전에는 보고서 수를 공개하지 않는다.
3. 버튼을 누르면 기존 Report Hub 디자인 토큰을 사용하는 관리자 비밀번호 창을 연다.
4. 인증에 성공하면 현재 브라우저 탭에서 30분 동안 사용할 임시 인증키를 저장한다.
5. 인증 후에만 비공개 보고서 목록과 수량을 서버에서 가져온다.
6. 비공개 목록에서는 검색, 페이지당 표시 개수, 생성일 정렬을 지원한다.
7. `잠금`을 누르거나 인증키가 만료되면 비공개 목록을 즉시 지우고 공개 전체 목록으로 돌아간다.
8. `?category=Private`로 직접 들어온 경우에도 같은 비밀번호 창을 먼저 표시한다.

### 비공개 보고서 열기

1. 링크 형식은 `/archive/private/?report=<보고서 ID>`로 통일한다.
2. 뷰어 페이지에는 원문이 포함되지 않는다.
3. 유효한 임시 인증키가 있을 때만 Worker에서 원문을 가져온다.
4. 인증키가 없거나 만료되면 비밀번호 입력 화면을 표시한다.
5. 가져온 HTML은 부모 페이지의 인증키에 접근할 수 없는 sandbox iframe 안에서 표시한다.
6. 비공개 페이지는 검색 엔진이 수집하지 않도록 `noindex, nofollow`를 사용한다.

### 관리자 통합 화면

1. 기존 관리자 인증이 끝난 뒤 `비공개 보고서 관리` 영역을 표시한다.
2. 독립 실행형 HTML 파일과 선택적 썸네일을 업로드할 수 있다.
3. 제목, 설명, 작성일, 출처 수, 태그를 입력하고 수정할 수 있다.
4. HTML 교체, 썸네일 교체, 삭제를 지원한다.
5. 삭제는 대상 제목을 다시 확인한 뒤 실행하고 R2 원문, 썸네일, D1 메타데이터를 함께 제거한다.
6. 기존 공개 보고서를 자동으로 비공개 전환하지 않는다. 공개 Git 기록에서 원문을 제거하는 작업은 별도 이관 절차가 필요하기 때문이다.

초기 업로드 범위는 단일 HTML 파일이다. HTML 안에 포함된 이미지 또는 HTTPS 외부 이미지는 사용할 수 있다. 별도 로컬 자산이 들어 있는 ZIP 묶음은 이번 범위에서 제외한다.

## 4. 인증과 접근 제한

### 임시 세션

- `POST /private-session`이 관리자 비밀번호를 확인한다.
- 성공 시 Web Crypto로 32바이트 임의 인증키를 만든다.
- 브라우저에는 원본 인증키를 반환하고 D1에는 SHA-256 결과만 저장한다.
- 인증키 유효기간은 발급 시점부터 30분이다.
- 브라우저는 인증키를 `sessionStorage`에만 저장한다. 관리자 비밀번호는 저장하지 않는다.
- `DELETE /private-session`은 현재 인증키를 폐기한다.

### 로그인 실패 제한

- 요청 IP는 별도 Worker 비밀값과 함께 SHA-256 처리한 식별값으로만 저장한다.
- 15분 안에 비밀번호가 5회 틀리면 30분간 새 로그인을 막는다.
- 인증 성공 시 해당 실패 기록을 제거한다.
- 인증 API는 성공과 실패 모두 비공개 자료의 존재 여부를 추가로 노출하지 않는다.

### 공통 보호 규칙

- 비공개 API는 허용된 Report Hub 출처에서만 호출할 수 있다.
- 모든 비공개 응답은 `Cache-Control: private, no-store`를 사용한다.
- 인증키는 URL, 로그, Git 저장소에 넣지 않는다.
- Worker의 `ADMIN_PASSWORD`, 세션 비밀값, R2 버킷은 공개 소스에 값을 기록하지 않는다.
- 유효하지 않은 인증키는 `401`, 만료된 인증키는 `401`, 로그인 차단은 `429`로 응답한다.

## 5. 저장 구조

### R2

- 바인딩: `PRIVATE_REPORTS`
- HTML 키: `reports/<id>/report.html`
- 썸네일 키: `reports/<id>/cover.<확장자>`
- 버킷은 공개 URL을 만들지 않는다.

### D1 테이블

`private_reports`

- `id`: URL에 사용하는 고유 ID
- `title`, `summary`: 목록 표시 정보
- `created_at`, `updated_at`: 생성 및 수정 시각
- `display_date`: 카드 작성일
- `source_count`: 출처 수
- `tags_json`: 태그 JSON
- `html_key`, `cover_key`: R2 객체 키
- `cover_type`: 썸네일 MIME 유형

`private_admin_sessions`

- `token_hash`: 인증키 SHA-256 값
- `created_at`, `expires_at`: 발급 및 만료 시각

`private_auth_attempts`

- `fingerprint`: IP 기반 비가역 식별값
- `window_started_at`, `failure_count`, `blocked_until`: 실패 횟수와 차단 시각

## 6. API 경계

- `POST /private-session`: 비밀번호 확인 및 임시 인증키 발급
- `DELETE /private-session`: 임시 인증키 폐기
- `GET /private-reports`: 인증된 비공개 목록
- `POST /private-reports`: HTML, 썸네일, 메타데이터 업로드
- `GET /private-reports/:id`: 인증된 메타데이터
- `GET /private-reports/:id/content`: 인증된 HTML 원문
- `GET /private-reports/:id/cover`: 인증된 썸네일
- `PUT /private-reports/:id`: 메타데이터 및 선택적 파일 교체
- `DELETE /private-reports/:id`: 원문, 썸네일, 메타데이터 삭제

목록 API는 R2 객체 키와 내부 인증 정보를 반환하지 않는다. 모든 관리 API는 임시 인증키를 `Authorization: Bearer <인증키>` 헤더로 받는다.

## 7. 화면 설계

기존 `DESIGN.md`를 그대로 사용한다.

- 색상: `--rh-primary`, `--rh-paper`, `--rh-soft`, `--rh-ink`, `--rh-sub`, `--rh-muted`, `--rh-border`, `--rh-danger`
- 형태: 기존 카테고리 버튼, 관리자 입력창, 18px 관리 카드 반경을 재사용한다.
- 아이콘: 기존 선형 SVG 아이콘 체계의 자물쇠를 사용한다. 이모지는 사용하지 않는다.
- 데스크톱: 현재 왼쪽 카테고리 목록에 `비공개`를 둔다.
- 860px 이하: 기존 모바일 카테고리 제어 안에 같은 버튼을 둔다.
- 비밀번호 창: 제목, 짧은 설명, 비밀번호 입력, 확인, 취소만 제공한다.
- 상태: 확인 중, 잘못된 비밀번호, 차단, 만료, 빈 목록, 네트워크 오류를 같은 자리에서 명확히 표시한다.
- 390px, 768px, 1280px에서 가로 스크롤이 없어야 한다.

## 8. 오류 처리

- R2 업로드가 실패하면 D1 메타데이터를 남기지 않는다.
- 메타데이터 저장이 실패하면 새로 업로드한 R2 객체를 정리한다.
- 파일 교체 중 실패하면 기존 파일과 메타데이터를 유지한다.
- 삭제 중 일부만 실패하면 남은 대상을 다시 정리할 수 있도록 오류를 표시하고 관리 목록을 다시 읽는다.
- API 연결 실패 시 공개 도서관 기능에는 영향을 주지 않고 비공개 영역만 오류 상태로 둔다.
- 만료 응답을 받으면 메모리와 `sessionStorage`에서 인증키를 즉시 제거한다.

## 9. 검증 기준

### 자동 검증

- 올바른 비밀번호 발급, 잘못된 비밀번호, 5회 실패 차단, 만료, 폐기
- 원본 인증키가 D1에 저장되지 않는지 확인
- 인증 없는 목록, 본문, 썸네일, 업로드, 수정, 삭제가 모두 거부되는지 확인
- 업로드 후 목록과 본문이 일치하고 삭제 후 접근할 수 없는지 확인
- 공개 아카이브 HTML과 manifest에 비공개 제목이나 원문이 없는지 확인
- 기존 Draft, 조회수, 인기글, 댓글 테스트가 유지되는지 확인

### 실제 브라우저 검증

- 390px, 768px, 1280px에서 잠금, 인증, 빈 목록, 목록, 만료, 오류 상태 확인
- 직접 비공개 URL에서 인증 전 원문 요청이 발생하지 않는지 확인
- 인증 후 보고서 렌더링과 잠금 후 즉시 제거 확인
- 관리자 화면에서 업로드, 수정, HTML 교체, 썸네일 교체, 삭제 확인
- 콘솔 오류와 가로 넘침이 없는지 확인

## 10. 배포와 복구

1. 새 D1 migration을 로컬에서 먼저 적용한다.
2. R2 비공개 버킷과 Worker 바인딩을 준비한다.
3. Worker의 세션 비밀값을 secret으로 등록한다.
4. Worker 테스트와 로컬 브라우저 검증을 통과시킨다.
5. D1 원격 migration을 적용하고 Worker를 배포한다.
6. GitHub Pages를 배포한 뒤 실제 도메인에서 전체 흐름을 다시 검증한다.
7. 문제가 생기면 Pages 커밋은 `git revert`로 되돌리고 Worker는 직전 버전을 재배포한다. D1 테이블과 R2 객체는 삭제하지 않아 복구 가능성을 남긴다.

## 11. 완료 조건

- 관리자 인증 전에는 비공개 제목, 썸네일, 본문이 네트워크 응답과 공개 저장소에 존재하지 않는다.
- 인증 후 도서관과 직접 URL에서 같은 비공개 보고서를 볼 수 있다.
- 잠금, 만료, 로그아웃 후에는 다시 인증해야 한다.
- 관리자 화면에서 비공개 보고서의 등록, 수정, 삭제가 실제 서버 저장 상태에 반영된다.
- 기존 공개 도서관과 보고서 기능 회귀가 없다.
