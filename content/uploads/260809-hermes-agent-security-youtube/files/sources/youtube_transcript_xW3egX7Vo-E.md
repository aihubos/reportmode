## 📌 주요 내용 요약

### 1. 웹/앱 보안 vs AI/LLM 보안의 평행선
- **SQL 인젝션 → 프롬프트 인젝션 (Prompt Injection)**
  - 직접 인젝션: 체봇의 시스템 프롬프트를 무시하고 악성 지시 수행.
  - 간접 인젝션: 문서, 이미지, 웹페이지 등에 숨겨진 악성 프롬프트가 실행되는 현상 (훨씬 위험).
- **파라미터 바인딩 (Parameter Binding) 방어 개념**
  - 전통적 웹 방어: 명령어와 데이터를 분리된 채널로 전달.
  - LLM 방어: 근본적 통로 분리가 어려우므로 최소 권한 부여(Least Privilege), 시스템 프롬프트 가드레일, 사람 승인 게이트(Human-in-the-loop) 적용.
- **사회공학적 해킹 → 탈옥 (Jailbreak)**
  - 감정 호소, 역할극(소설 작가, 폭발물 전문가 등)으로 제한 해제.
  - 실시간 응답 모니터링/트레이싱, 모델 강제 다운그레이드(예: Anthropic의 Mitros/Pable 모델 제어) 등으로 방어.
- **하드코딩된 API 키 → 시스템 프롬프트 유출 (System Prompt Leakage)**
  - 디스어셈블러로 앱/코드 내 API 키 탈취하듯, 프롬프트 출력 지시로 내부 프롬프트 유출.
  - 원칙: 비밀 정보/API 키는 시스템 프롬프트에 절대 포함시키지 않음.

### 2. AI 에이전트 권한 관리 & 보안 원칙
- **읽기/쓰기 권한 분리**: 일반 에이전트에겐 읽기(Read) 권한만 부여.
- **매니저 에이전트 승인**: 쓰기/실행 권한은 매니저 에이전트를 거치도록 설계.
- **감시 에이전트 (Audit/Auditor Agent)**: 비하인드에서 에이전트 간 대화를 감시하고 위험 행동 감지.
- **상세 로깅 (Logging)**: 에이전트의 권한 사용 시점과 사유를 모두 기록해 추적성 확보.

### 3. 클로드(Claude) 활용 및 개인정보 감형 처리
- 클로드 프로젝트(Project), 커넥터(Connectors), 스킬(Skills) 소개.
- 보안 스킬 및 로컬 감형 스크립트를 활용해 내부 데이터 유출 방지.
