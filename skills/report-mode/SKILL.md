# Report Mode

검증 가능한 자료와 실제 시각자료를 사용해 한국어 HTML 보고서를 완성하라.

## 결과물

- 브라우저에서 바로 열 수 있는 독립형 HTML 파일 1개를 만들라.
- 파일명을 한국시간 생성일 기준 `YYMMDD-english-slug.html`로 만들라.
- 화면에는 `YYMMDD · 보고서 제목`, 본문에는 `YYYY.MM.DD KST`를 표시하라.
- CSS를 HTML 안에 포함하고 PC, 390px 모바일, 인쇄 화면을 지원하라.
- 기사, 데이터, 로고, 실제 사진, 생성 이미지를 문서 최하단 전체 출처 표에 기록하라.

## 보고서 깊이

사용자 표현을 우선해 다음 중 하나를 선택하라.

### 일반 보고서

- 기본값으로 사용하라.
- 5분 안에 읽는 심플한 형식으로 작성하라.
- 한 문장 결론, 핵심 요약, 표 1~2개, 장단점, 판단 기준, 전체 출처만 남기라.
- 반복 설명과 긴 배경 설명을 덜어내라.

### 심층보고서모드

- 사용자가 `심층보고서모드`, `심층 보고서`, `매우 상세하게`라고 요청할 때 사용하라.
- 조사 질문과 방법, 산업·기업 배경, 핵심 데이터, 경쟁 비교, 근거별 찬반 논리, 반대 관점, 세 가지 이상 시나리오, 리스크, 실행 조건, 한계, 상세 결론, 출처 신뢰도를 포함하라.
- 표를 3개 이상 적극 사용하되 근거 없는 분량 늘리기를 금지하라.

## Hermes 서브에이전트 오케스트레이션

- 최종 취합과 보고서 작성은 `openai/gpt-5.6-sol` 부모가 담당하라.
- 자료조사는 `delegate_task(tasks=[...])`로 병렬 위임하라.
- 현재 Hermes는 작업마다 모델을 지정하지 않는다. 자식 모델은 `config.yaml`의 `delegation.model`을 사용하므로 존재하지 않는 `model` 인자를 만들지 말라.
- 조사 모델은 `openai/gpt-5.6-terra`를 기본으로 사용하라. 빠른 대안 프로필에서는 `openai/gpt-5.6-luna`를 사용하라.
- 일반 보고서는 두 자식을 한 번에 실행하라.
  1. 공식 자료, 핵심 사실, 수치와 날짜 조사
  2. 시장·경쟁, 실제 사진, 로고 지침, 라이선스 조사
- 심층보고서는 기본 동시 한도 3개를 지켜 두 파동으로 실행하라.
  1. 1차 3개: 공식·재무/시장·제품/기술
  2. 2차 2개: 경쟁/반대근거·사진/로고/라이선스
- 각 자식에게 주제, 기간, 독자, 담당 범위, 추측 금지, 출력 형식을 `context`에 완전하게 전달하라. 자식은 부모 대화를 모른다고 가정하라.
- 각 결과를 `주장 | URL | 발행일 | 확인일 | 출처 유형 | 사실/분석/전망/루머 | 상충 내용 | 시각자료·라이선스` evidence pack으로 받으라.
- 서브에이전트에게 최종 보고서나 상호 리뷰를 맡기지 말라. Sol 부모가 중복 제거, 충돌 표시, 최종 판단, HTML 작성, 이미지 생성을 책임지라.
- 일부 조사가 실패하면 해당 범위를 한 번 재시도하고, 끝내 실패하면 누락 범위를 보고서에 적으라.

## 이미지 생성 의무

- 모든 보고서 상단에 보고서 내용 기반 인포그래픽을 실제 생성하라. 프롬프트만 작성하고 끝내지 말라.
- 이미지 생성 도구 또는 설정된 이미지 API를 반드시 호출하라.
- 순백색 배경, 깔끔한 검은 손그림, 제한된 포인트색, 짧고 큰 한글을 사용하라.
- 왼쪽 위에 원형 `RM` 로고와 `리포트 모드`를 넣으라.
- 보고서 내용에 맞춰 핵심 피사체, 두들 아이콘, 화살표, 정보 배치를 바꾸라.
- 이미지 프롬프트에 목적, 독자, landscape 비율, 핵심 피사체, 구도, whiteboard doodle, 색감, 정확한 문구, 금지 조건을 포함하라.
- 한국어 문구에 `readable Korean typography`, `no garbled Hangul`, `large clean Korean text`를 포함하라.
- 확인된 숫자와 고유명사만 사용하고 가짜 수치, 랜덤 영어, 깨진 한글, 복잡한 패널을 금지하라.
- 생성 뒤 한글, 숫자, 고유명사, 잘림, 중복 오브젝트를 확인하고 문제가 있으면 최소 한 번 재생성하거나 보정하라.
- HTML에는 실제 이미지 파일을 넣고 `AI 생성 인포그래픽 · 공식 제품 이미지 아님`을 표시하라.
- 이미지 도구가 없거나 실패하면 생성한 척하지 말고 실제 오류를 알리라.

## 실제 사진과 기업 로고

- 기업·제품 리서치에서는 웹 검색으로 실제 제품 사진과 공식 로고를 적극 찾으라.
- 로고를 AI로 비슷하게 그리지 말고 공식 브랜드 사이트나 공식 미디어킷에서 확보하라.
- 브랜드 로고 사용 지침과 재사용 권한을 확인하고 허용되는 경우에만 사용하라.
- 로고 사용이 금지되면 회사명 워드마크와 독립 보고서 고지를 사용하라.
- 공식 발표 전 제품의 렌더, 유출 주장, 더미 모델을 실제 제품 사진이라고 부르지 말라.
- 다른 회사의 실제 제품 사진은 `폼팩터 비교 자료`처럼 정확한 비교 목적과 제품명을 표시하라.
- 재사용 권한을 확인할 수 없는 사진은 내려받지 말고 원문 링크 카드만 제공하라.

## 문서 스타일

사용자 요청을 우선하고, 없으면 `Toss Clean`을 사용하라.

- `Toss Clean`: 흰색 `#ffffff`, 본문 `#191f28`, 포인트 `#3182f6`, 마커 `#ffe066`
- `Ultra Violet`: 흰색, 본문 `#1d1830`, 일부 포인트 `#6d28d9`, 마커 `#e9d5ff`
- `Dark Mode`: 문서 `#171a21`, 본문 `#f7f7f2`, 포인트 `#ff5c35`, 마커 `#ffd8cc`
- `Neon Signal`: 문서 `#0c1210`, 본문 `#eafff5`, 포인트 `#2cff9a`, 마커 `#ff2bd6`
- `Editorial Paper`: 문서 `#fffdf7`, 본문 `#1c1b17`, 포인트 `#ff5c35`, 마커 `#ffd8cc`

본문 글자색과 밑줄·마커색을 반드시 분리하라. 포인트색은 제목·표 헤더·아이콘에, 마커색은 밑줄·마커에 사용하라.

## 표·이모티콘·구조

- 사양, 수치, 경쟁사, 시나리오, 출처를 실제 HTML 표로 구성하라.
- 섹션 제목과 상태 표시에 🧭 📱 📊 ✅ ⚠️ 🔎 🧾를 적극 사용하라.
- 이모티콘을 정보 탐색에만 쓰고 문장마다 반복하지 말라.
- 표지, 한 문장 판단, 핵심 수치, 사양 표, 장단점, 판단 기준, 최종 판단을 포함하라.

## 근거 규칙

1. 공식 자료와 핵심 URL을 직접 확인하라.
2. 공식 발표, 언론 보도, 공급망 정보, 개인 의견을 분리하라.
3. 중요한 문장을 사실, 분석, 전망, 루머로 구분하라.
4. 상충하는 수치를 합치지 말고 범위와 충돌을 함께 표시하라.
5. 기사 전문을 복제하지 말고 제목, 발행처, URL, 날짜만 남기라.
6. 원문에 없는 내용을 사실처럼 만들지 말라.

## 최하단 전체 출처 표

문서의 마지막 요소를 반드시 전체 출처 표로 끝내라.

`유형 | 자료명 | 제공자·저작자 | URL | 날짜 | 라이선스·상태 | 사용 범위`

기사·논문·공식 문서뿐 아니라 로고, 실제 사진, 더미 사진 링크, AI 생성 이미지와 생성일도 모두 포함하라.
