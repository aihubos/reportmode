# Report Mode

출처가 확인되는 내용만 사용해 비전공자도 읽기 쉬운 매거진형 HTML 보고서를 만든다.

## 결과물

- 최종 산출물은 브라우저에서 바로 열 수 있는 독립형 HTML 파일 1개다.
- 파일명은 한국시간 생성일 기준 `YYMMDD-english-slug.html`로 만든다.
- 화면에는 `YYMMDD · 보고서 제목`, 본문에는 `YYYY.MM.DD KST`를 표시한다.
- CSS는 HTML 안에 포함한다. 별도 서버나 빌드 도구를 요구하지 않는다.
- PC, 390px 모바일, 인쇄 화면을 모두 지원한다.

## 기본 디자인 계약

- 레이아웃: 따뜻한 매거진형 에디토리얼
- 강조색: `#ff5c35`
- 배경색: `#f4efe4`
- 문서색: `#fffdf7`
- 본문색: `#1c1b17`
- 보조색: `#716d63`
- 제목: `Noto Serif KR`, 데스크톱 표지 72px, 굵고 넓은 여백
- 본문: `Noto Sans KR`, 17px, 줄 간격 1.72
- 콘텐츠 최대 폭: 960px
- 카드 모서리: 18px
- 제목은 serif, 본문은 sans-serif로 대비한다.
- 표지에는 유형명, 생성일, 큰 제목, 한 줄 설명, 출처 수를 둔다.

## 하이라이트 계약

- 핵심 문장 뒤에 `#ff5c35` 마커 띠를 표준 강도 약 72%로 표시한다.
- 적극 사용 모드로 핵심 수치, 최종 판단, 위험 경고, 섹션별 핵심어를 강조한다.
- 한 문단에 두 번 이상 반복하지 않는다.
- 출처가 없는 주장이나 단순 수식어는 강조하지 않는다.
- 인쇄 가독성이 떨어지면 투명도만 낮춘다.

## 필수 구조

- 표지
- 한 문장 판단과 경영진 요약
- 핵심 수치 카드
- 사양 또는 핵심 데이터 표
- 장점과 단점 병렬 비교
- 구매 또는 실행 전 판단 기준
- 최종 판단
- 출처 목록과 확인 범위

주제에 필요하면 타임라인, 비교표, 인용문, 위험 요소를 추가한다.

## 근거 규칙

1. 사용자가 제공한 URL을 모두 확인한다. 하나라도 열리지 않으면 실패한 출처를 알리고 추측으로 채우지 않는다.
2. 공식 발표, 언론 보도, 공급망 정보, 개인 의견을 섞지 않는다.
3. 중요한 문장은 사실, 분석, 전망, 루머 중 성격이 드러나게 쓴다.
4. 상충하는 수치는 임의로 합치지 말고 범위와 충돌 사실을 함께 적는다.
5. 기사 전문을 복제하지 않는다. 제목, 발행처, URL, 발행일 또는 확인일만 남긴다.
6. 원문에 없는 내용을 사실처럼 만들지 않는다. 불확실하면 불확실하다고 쓴다.
7. 한국어는 짧고 명확하게 쓰고 필요한 전문용어는 바로 풀어서 설명한다.

## 제작 순서

1. 요청에서 주제, 목적, 독자, 언어, 출처를 정리한다.
2. 출처를 확인하고 핵심 사실, 충돌 지점, 미확정 정보를 분리한다.
3. 먼저 한 문장 결론과 목차를 만든다.
4. 필수 구조에 근거를 배치하고 주요 주장에 실제 출처 링크를 연결한다.
5. 디자인 계약을 CSS 변수 `--accent`, `--paper`, `--ink`, `--muted`, `--title-font`, `--body-font`로 구현한다.
6. 장점과 단점은 같은 폭과 비슷한 정보량으로 구성하고 모바일에서는 세로로 쌓는다.
7. 모바일과 인쇄용 미디어 쿼리를 포함한다.
8. 저장 후 제목, 날짜, 출처 링크, 모바일 넘침을 직접 확인한다.

## Apple 폴더블 보고서 예시 방향

- 공식 발표 전이라는 상태를 표지에 표시한다.
- 예상 화면 크기와 가격은 출처별 차이를 보존한다.
- 장점은 대화면 멀티태스킹과 Apple 생태계 연속성을 다룬다.
- 단점은 1세대 내구성, 무게, 가격, 수리비를 다룬다.
- 실측 무게, 실제 배터리 시간, 화면 주름, 앱 최적화, 보증 정책을 확인한 뒤 구매하도록 결론을 낸다.
