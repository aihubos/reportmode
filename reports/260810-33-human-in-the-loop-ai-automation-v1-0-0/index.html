HARD BOUNDARY

밖으로 나가거나 되돌리기 어려운 실행은 명시적 승인을 거친다.

ONE-MINUTE BRIEF

AI에게 일을 맡겨도 책임까지 넘기면 안 된다

Human-in-the-loop는 사람이 매 단계 끼어드는 구조가 아니다. 사고가 커지는 경계에만 사람이 남고, 나머지는 AI가 빠르게 처리하도록 역할을 나누는 설계다.

REPORT HUB VERDICT

AI는 수집·정리·초안을 맡기고, 사람은 맥락·책임·외부 실행을 승인해야 한다.

보고서 공개 전 사실과 표현을 확인하고, 메시지 발송 전 수신자와 내용을 확인하고, 삭제·결제·권한 변경 전에는 별도 인증과 복구 경로를 확인한다. 이 세 문턱만 분명해도 자동화는 훨씬 덜 불안해진다.

GATE 01맥락

보고서·위키에서 사실, 의도, 병합 범위를 사람이 확인한다.

GATE 02발신

수신자·채널·첨부·공개 범위를 보고 승인한다.

GATE 03권한

삭제·결제·권한 변경·민감정보는 별도 경계로 둔다.

DEFAULT읽기

WHY I CHANGED THE GOAL

자동화율을 높이는 것이 목표가 아니었던 이유

처음에는 많이 맡길수록 좋은 줄 알았다.

자료를 찾고, 문서를 정리하고, 메시지를 만들고, 파일까지 옮겨주면 내가 볼 일이 거의 없어지는 구조.

약간 자비스 같은 느낌이었다.

근데 실제 운영은 조금 달랐다.

AI가 초안을 빠르게 만드는 것과 그 초안을 바로 공개하는 것은 전혀 다른 일이었다. 비슷한 위키 페이지를 찾아주는 것과 기존 기록을 덮어쓰는 것도 달랐다. 메시지를 잘 쓰는 것과 지금 이 사람에게 보내도 되는지 판단하는 것도 달랐다.

빠르게 틀리면 생산성이 올라가는 게 아니다. 재작업과 설명할 일이 더 빨리 생긴다.

그래서 목표를 바꿨다.

더 많은 자동화가 아니라, 사람이 꼭 봐야 하는 순간만 남기는 것.

NIST AI RMF도 조직이 human-AI 구성의 역할과 책임을 구분하고, 주기적 검토와 중단·비활성화 책임을 명확히 두도록 제시한다. [출처 1]

이 주제가 더 이상 먼 미래 이야기가 아닌 이유도 있다. OWASP는 2026년판 Agentic Applications Top 10을 별도로 공개해, 계획하고 도구를 쓰고 실제 행동하는 에이전트의 위험을 독립적인 운영 주제로 다루고 있다. [출처 7]

AI가 90%를 완성해도 마지막 10%가 회사의 이름, 내 이름, 외부 신뢰를 결정한다.

02

정리와 병합은 다르다

비슷한 문서를 찾는 건 검색이지만, 어떤 기록을 남기고 지울지는 맥락 판단이다.

03

제안과 실행은 다르다

에이전트가 “이렇게 하자”고 말하는 것과 실제 도구가 움직이는 사이에 승인 경계가 필요하다.

THE THREE HUMAN GATES

사람이 빠지면 안 되는 세 지점

사람이 해야 할 일은 AI가 쓴 문장을 처음부터 다시 쓰는 것이 아니다. 맥락이 틀리면 손실이 커지는 경계에서 승인하는 것이다.

01FACT · CONTEXT

사실과 맥락

보고서 공개와 위키 병합 전에는 “문장이 자연스러운가”보다 “이 자료가 이 결론을 정말 지지하는가”를 본다.

AI출처 수집, 숫자 대조, 중복 탐지, diff와 병합안 작성
사람주장의 강도, 빠진 반론, 기록을 남길 이유, 덮어써도 되는 범위 판단
02EXTERNAL COMMS

외부 발신

메시지, 이메일, 공개 게시물은 전송 전에 수신자·채널·본문·첨부·시간을 한 화면에서 확인한다.

AI문안 작성, 수신자 후보, 첨부 파일 목록, 발송 preview 생성
사람지금 보내는 게 맞는지, 말투와 공개 범위가 맞는지 명시적으로 승인
03IRREVERSIBLE · PRIVILEGED

삭제·결제·민감정보

되돌리기 어렵거나 돈·권한·개인정보가 걸린 작업은 기본적으로 막고, 필요한 경우에만 권한을 잠깐 연다.

AI삭제 후보, 결제안, 권한 변경안, 마스킹 결과를 제안
사람백업·금액·대상·보유 권한·민감정보 여부를 확인하고 별도 인증
내 운영 원칙: AI가 판단을 제안할 수는 있지만, 실행 권한까지 자동으로 따라오게 만들지 않는다. OWASP도 high-impact·irreversible 작업에 명시적 승인, 실행 전 preview, audit trail, 중단·rollback을 권고한다. [출처 2]
HUMAN-IN-THE-LOOP MATRIX

자동화 단계별 담당자 표

모든 작업을 승인받게 만들면 자동화가 느려진다. 반대로 모든 작업을 자동 실행하면 작은 오류가 외부 사고로 번진다. 그래서 작업 위험에 따라 4단계로 나눴다.

고객정보·계약서·인사자료는 “AI가 잘 처리하나”보다 외부 전송이 필요한지부터 판단한다.

LINK

메일·드라이브·메신저를 연결할수록 도구별 read/write 범위와 하위 처리 흐름을 분리한다.

PII

민감정보 경계

입력 전에 마스킹하고, 로그와 메모리에도 그대로 남지 않도록 저장 범위를 제한한다.

OWN

책임자와 기록

누가 승인했고 무엇이 실행됐는지 남기고, 실패하면 누가 멈출지 owner를 정한다.

개인적으로는 이 부분이 제일 중요했다.

AI 에이전트는 계속 똑똑해질 것이다. 지금보다 훨씬 더 많은 일을 알아서 할 수 있게 될 것이다.

하지만 권한이 커질수록 사용자가 더 잘 검수해야 한다.

검수는 꼭 사용자가 한다.

이 원칙을 포기하지 않으면서, 사람이 반복해서 볼 필요가 없는 부분은 계속 줄이는 것이 내가 원하는 자동화다.

30 / 60 / 90 DAYS

작게 시작해서 승인 경계를 먼저 만든다

처음부터 결제·삭제까지 붙이지 않는다. read-only 업무로 성능과 로그를 확인한 다음 write 권한을 단계적으로 연다.

30D

작업과 권한 목록화

에이전트가 접근하는 도구와 행동을 한 장에 적는다.

  • read / write / external / irreversible 분류
  • 개인정보·기밀 포함 여부
  • 작업별 owner와 중단 버튼
60D

Preview와 승인 구현

실행 전에 대상과 변경 결과를 보여준다.

  • 메시지·게시·병합 diff
  • 정확한 action에 묶인 승인
  • read-only 기본값과 allowlist
90D

실패 훈련과 재조정

승인 피로와 누락을 함께 점검한다.

  • 삭제·발송·권한 오작동 모의훈련
  • override·rollback·재시도 기록
  • 불필요한 승인 제거, 고위험은 강화
RISKS & COUNTERPOINTS

사람을 넣는 것만으로 안전해지는 것은 아니다

Human-in-the-loop도 설계를 잘못하면 승인 버튼만 습관적으로 누르는 구조가 된다. EU AI Act의 human oversight 조항은 high-risk AI에 대해 automation bias를 인지하고, 출력 무시·override·reverse·stop이 가능해야 한다고 명시한다. 이 의무가 모든 자동화에 그대로 적용되는 것은 아니지만, 운영 설계 기준으로 참고할 만하다. [출처 4]

×승인 버튼 하나만 넣으면 안전하다
✓대상·변경값·영향이 안 보이면 사람도 자동으로 승인한다. preview가 먼저다.
×모든 작업을 사람이 확인해야 한다
✓read-only·되돌릴 수 있는 작업은 자동화하고 위험 경계에만 승인 단계를 둔다.
×로그만 남기면 책임이 명확하다
✓로그를 볼 owner, 중단 권한, 복구 절차가 없으면 기록은 사후 흔적에 그친다.
×AI가 제안했으니 판단 책임도 AI다
✓AI는 판단 재료를 만들 수 있지만, 외부에 영향을 주는 최종 선택은 사람과 조직이 책임진다.

모든 단계가 아니라 위험 경계만 확인하면 된다. 수집·정리·초안·비교는 자동으로 돌리고, 공개·발송·병합·비가역 실행에서만 멈추면 자동화 이점은 대부분 유지된다.
어떤 작업부터 read-only로 시작하면 좋나요?
웹 조사, 파일 목록 조회, 로그 요약, 위키 중복 탐지처럼 상태를 바꾸지 않는 작업부터 시작한다. 결과와 로그가 안정적인지 본 뒤 제한된 write 권한을 추가한다.
위키 병합도 꼭 사람이 봐야 하나요?
중복 후보 탐지와 diff 작성은 AI가 잘할 수 있다. 하지만 실패 기록, 결정 이유, 오래된 문맥을 지워도 되는지는 단순 유사도로 결정하기 어렵다. 원본 보존과 rollback이 가능한 상태에서 사람이 canonical을 정하는 편이 안전하다.
외부 발신 승인 화면에는 무엇이 보여야 하나요?
수신자, 채널, 제목·본문, 첨부, 발송 시각, 공개 범위, 에이전트가 사용한 계정과 권한을 한 화면에 보여주는 것이 좋다. 승인 후 내용이 바뀌면 기존 승인을 재사용하지 않는다.
삭제와 결제는 AI에게 절대 맡기면 안 되나요?
AI가 후보를 찾고 금액·대상·근거를 준비하는 것은 가능하다. 다만 실제 실행은 한도, 별도 인증, 백업 또는 취소 가능성, 중복 방지, 감사 로그를 갖춘 뒤 사람 승인을 거치는 편이 좋다.
Human-in-the-loop만 있으면 보안이 충분한가요?
아니다. 최소 권한, 도구 allowlist, 입력·출력 검증, 민감정보 마스킹, 로그, 중단·rollback과 함께 써야 한다. OWASP도 사람 승인과 least privilege, output validation을 별도 통제로 함께 제시한다. [출처 2] [출처 3]
