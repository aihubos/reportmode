EXECUTIVE SUMMARY

영상의 방향은 맞지만,
두 가지는 반드시 바로잡아야 합니다

영상은 “원문을 통째로 읽는 비용을 줄이고, 먼저 구조를 만든다”는 핵심을 잘 설명합니다. 다만 현재 공식 문서 기준으로는 자료 유형별 처리 방식과 결과물의 중요도가 영상 설명보다 더 세분화되어 있습니다.

의사결정용 한 문장

“지식을 한 번 구조화하고 반복 질의 비용을 낮춘다”는 판단은 타당하지만, 메모·PDF 중심 자료는 초기 그래프 구축에도 모델 호출이 필요할 수 있으므로 실제 절감률은 자료 구성과 질문 방식에 따라 달라집니다.

01

Graphify의 본질

AI용 지하철 노선도

파일을 노드와 관계로 바꾸고, AI가 질문과 관련된 작은 부분 그래프부터 찾아가게 합니다. 원문 전체를 매번 읽는 방식보다 탐색 범위를 줄이는 것이 핵심입니다. 2

02

LLM Wiki와의 관계

위키는 지식층, Graphify는 탐색층

LLM Wiki는 AI가 지속적으로 가꾸는 Markdown 지식베이스 패턴이고, Graphify는 구조·관계·질의를 그래프 형태로 제공하는 별도 도구입니다. 현재 Graphify는 --wiki 출력도 지원합니다. 25

03

가장 큰 오해

“전부 무토큰”은 아님

코드는 로컬 AST 분석이 가능하지만, 문서·PDF·이미지·영상은 의미 관계를 뽑기 위해 모델 백엔드를 사용합니다. 절감은 주로 이후 반복 질의에서 나타납니다. 2

HOW IT WORKS

Graphify는 여섯 단계로
자료를 “질문 가능한 지도”로 바꿉니다

파일을 모으는 것에서 끝나지 않고, 구조 추출 → 그래프 구축 → 군집화 → 핵심 노드 분석 → 질의 가능한 결과물 생성으로 이어집니다. 공식 파이프라인은 detect, extract, build, cluster, analyze, report/export 순서입니다. 3

LOCAL ENGINE

코드: Tree-sitter AST

함수, 클래스, 호출, import, 상속 같은 구조를 로컬에서 결정론적으로 추출합니다. 코드 전용 모드는 API 키 없이 사용할 수 있습니다. 2

SEMANTIC ENGINE

문서·미디어: 모델 의미 추출

Markdown, PDF, 이미지, 영상의 개념과 관계는 Claude·OpenAI·Gemini·Ollama 등 설정한 백엔드가 해석할 수 있습니다. 민감 자료라면 백엔드와 전송 범위를 먼저 검토해야 합니다. 2

LLM WIKI × GRAPHIFY

둘 중 하나를 고르기보다,
역할을 나누면 더 명확합니다

LLM Wiki는 “어떤 지식을 오래 남기고 갱신할 것인가”에 강하고, Graphify는 “어디서부터 읽고 어떤 관계를 따라갈 것인가”에 강합니다. 현재 Graphify의 --wiki 옵션 때문에 경계는 일부 겹치지만 운영 목적은 구분하는 편이 좋습니다.

추천 조합: 원문은 별도 보존하고, Graphify로 구조·관계를 만든 뒤, 오래 유지할 핵심 지식만 Markdown Wiki로 정제합니다. 즉 Graphify는 “찾는 지도”, LLM Wiki는 “남기는 백과사전”으로 두면 운영이 단순해집니다.

TOKEN ECONOMICS

토큰 절감은 “구축 비용 0”이 아니라
“반복 읽기 비용을 줄이는 것”입니다

영상의 약 5배 절감은 해당 사용자의 25개 Markdown 파일 실습 결과입니다. Graphify 프로젝트 사이트는 별도 혼합 코퍼스에서 평균 질의 비용 71.5배 감소를 보고하지만, 두 수치는 자료·질문·기준선이 달라 직접 비교할 수 없습니다. 13

절감이 생기는 지점은 두 번째 질문부터

초기에는 파일 탐색·구조 추출·군집화 비용이 듭니다. 이후 질문마다 원문 전체를 다시 읽지 않고 관련 서브그래프만 꺼내면서 누적 이점이 커집니다.

총 비용 = 초기 그래프 구축 비용 + 반복 질의의 작은 서브그래프 비용
기존 방식 = 매 질문마다 원문 검색·재독·재조합 비용
따라서 한 번만 묻는 작은 폴더보다, 계속 질문하는 큰 프로젝트에서 경제성이 커집니다.

절감 가능성이 큰 경우

코드베이스가 크고, 같은 영역을 여러 세션·여러 에이전트가 반복 탐색하며, 관계 질문이 많을 때입니다.

효과가 제한적인 경우

문서가 몇 개뿐이거나, 한 번 요약하고 끝나는 작업, 질문 범위가 늘 매번 완전히 바뀌는 작업입니다.

비정형 자료 중심의 주의

Markdown·PDF·이미지 중심 코퍼스는 의미 추출 단계에서 모델 호출이 필요할 수 있어 초기 비용과 개인정보 전송 범위를 확인해야 합니다.

Graphify는 원문을 대체하지 않습니다. 그래프는 탐색 순서를 개선하는 색인·관계층이며, 중요한 판단은 출처 파일과 신뢰도 태그를 다시 확인해야 합니다.

오래된 그래프

운영

파일이 바뀌었는데 그래프를 갱신하지 않으면 이전 구조가 계속 질의 결과를 지배할 수 있습니다.

통제: 변경 후 --update, 대규모 리팩터링 후 --force 재추출.

추론 관계의 과신

정확성

모든 엣지가 원문에 명시된 것은 아닙니다. INFERRED·AMBIGUOUS 관계는 오류 가능성이 있습니다.

통제: EXTRACTED와 INFERRED를 구분하고 중요한 답은 원문 위치를 확인.

민감 문서의 외부 전송

보안

코드는 로컬 AST가 가능하지만 문서·PDF·이미지의 의미 추출은 설정한 모델 백엔드를 사용할 수 있습니다.

통제: 허용 자료만 분리하고, 로컬 Ollama·사내 게이트웨이 또는 승인된 API 사용.

시각화 과부하

사용성

큰 그래프의 HTML은 렌더링이 무겁고, 복잡한 노선도처럼 보여 의사결정에 오히려 방해가 될 수 있습니다.

통제: --no-viz 또는 query 중심 운영, 커뮤니티별로 범위 축소.

빠른 버전 변화

유지보수

PyPI는 2026년 8월 5~8일 사이에도 여러 버전이 연속 공개됐습니다. 영상 명령과 현재 명령이 달라질 수 있습니다.

통제: graphify --version 확인 후 uv tool upgrade graphifyy와 스킬 재설치.

로컬 질의 로그

개인정보

공식 README에 따르면 query·path·explain 호출 메타가 로컬 JSONL 로그에 기록됩니다.

통제: 필요 시 GRAPHIFY_QUERY_LOG_DISABLE=1로 비활성화하고 로그 보관정책을 정함. 2
