EXECUTIVE SUMMARY

한 명의 AI와 대화하던 단계에서
AI 조직을 지휘하는 단계로 이동합니다

영상의 관점에서 중요한 변화는 “더 똑똑한 챗봇”이 아니라, 전문 역할을 가진 여러 에이전트가 도구와 데이터를 사용하고 서로 결과를 넘겨주는 운영 구조입니다.

HQ

한 문장 결론

에이전트 수가 늘수록 사용자가 모든 봇을 직접 관리하기보다, 하나의 “본사·참모실” 에이전트에게 업무를 맡기고 전문 에이전트를 배정하게 하는 구조가 중요해집니다. 다만 이메일·투자·문서 권한처럼 위험도가 높은 실행에는 사람이 승인하는 단계가 필요합니다.

01

단일 AI → AI 팀

사람과 한 에이전트의 협업에서, 여러 에이전트와 사람의 협업으로 중심이 이동합니다.

02

본사형 오케스트레이션

사용자는 본사 에이전트에게만 지시하고, 본사가 적합한 전문 에이전트를 호출합니다.

03

모델보다 도구 접근

VM, 플러그인, MCP, 이메일, Obsidian 등 실제 시스템에 접근하는 능력이 사용성을 좌우합니다.

04

지식과 실행의 결합

노트를 읽는 데서 끝나지 않고, 보고서 작성·메일 제안·이미지 생성·업무 관리로 이어집니다.

05

사람의 승인 필요

자동화 범위가 커질수록 권한, 오류, 비용, 보안 통제가 더 중요해집니다.

GROK BOT VS BUZZ VS HERMES

쉬운 시작, 높은 자유도, 기존 스킬 활용 중
무엇을 우선하느냐가 선택 기준입니다

아래 비교는 제공된 자막 속 발표자의 사용 경험과 주장에 근거합니다. 공식 기능표나 최신 가격 검증이 아니라 영상 내용을 빠르게 이해하기 위한 정리입니다.

비교 기준Grok BotBuzzHermes
핵심 포지션 가장 쉽게 시작하는 에이전트생성·플러그인·가상 PC를 묶어 빠르게 사용 직접 설계하는 오픈소스 에이전트 공간채널·스레드 중심의 작업 관리 스킬과 프로파일을 봇 팀으로 확장기존 Hermes 자산을 이어 쓰는 방식
실행 환경 에이전트별 클라우드 VM이 있다는 설명별도 Mac mini 대체 관점 Railway·Docker 등에 직접 배포하는 구조셀프 호스팅 가능 Hermes 환경과 봇 모드를 중심으로 사용기존 사용자 친화
모델 선택 발표자 기준 선택 폭이 상대적으로 제한적 Codex, xAI, Cursor 연계 등 목적별 모델 커스터마이징을 강조 Nous Portal 등을 통한 다양한 모델 활용을 강조
업무 조직 방식 본사 에이전트가 여러 봇을 생성·관리 슬랙처럼 채널에 여러 에이전트를 불러 협업 봇과 봇 사이의 커뮤니케이션을 강점으로 제시
도구·연동 VM, Obsidian, Gmail 등 플러그인 활용 사례 MCP·기존 스킬·모델·외부 서비스를 세밀하게 조합 기존 Hermes 스킬과 프로파일 자산을 봇에 연결
작업 관리 에이전트별 실행과 본사 지시 중심 스레드, Pulse, Inbox로 과거 작업과 알림을 관리 봇 협업 중심이며 자막에서는 세부 작업 관리 UI 설명이 적음
모바일 활용 가능하다고 설명 가능하다고 설명 촬영 시점 공식 모바일 앱 부재로 이동 중 활용성이 낮다고 평가
운영 난이도 낮음 설치·서버 운영 부담이 적다는 평가 높음 설치, 배포, 보안, 업데이트를 직접 관리 중간 기존 Hermes 경험과 스킬 자산이 있을수록 유리
가장 맞는 사용자 에이전트를 처음 쓰거나 원격 가상 PC가 필요한 사용자 모델·MCP·스킬을 목적별로 조합하고 싶은 빌더 이미 Hermes를 쓰고 있고 기존 스킬을 팀 단위로 확장하려는 사용자
REAL USE CASES

영상은 에이전트가 실제 시스템을 만질 때
가치가 커진다고 보여줍니다

사례의 공통점은 “답변 생성”이 아니라, 외부 데이터·앱·파일을 읽고 다음 에이전트에게 넘겨 결과물을 만드는 연결 작업입니다.

🗂️

원격 Obsidian

가상 컴퓨터에 Obsidian과 동기화 볼트를 두고, 사용자의 노트 조회·작성·저장을 원격으로 수행합니다.

VM → Obsidian → 노트 조회·저장
📈

투자·재무 보조

외부 데이터 MCP와 계좌 API를 연결해 리포트를 만들고, 추가 매수 여부 같은 행동을 조언하는 사례입니다.

시장 데이터 → 분석 에이전트 → 사람 판단
✉️

파트너십 메일

Gmail에서 제안 메일을 선별하고, 놓치기 쉬운 중요한 제안을 요약해 답변 방향을 제안합니다.

Gmail → 중요도 분류 → 답변 초안
📝

회의 정리

회의 내용을 수집해 정리하고, 이후 업무에서 다시 활용할 수 있는 지식 형태로 남깁니다.

회의 원문 → 요약 → 지식 저장
🎨

조사 → 이미지 생성

한 에이전트가 X에서 이미지를 조사하고, 다른 에이전트가 그 결과를 바탕으로 이미지 생성 MCP를 실행합니다.

조사 봇 → 생성 봇 → 결과 이미지
MULTI-AGENT OPERATING MODEL

본사 에이전트가 일을 나누고
사람은 중요한 지점만 승인합니다

영상에서 반복되는 사용 패턴을 하나의 업무 흐름으로 정리하면 다음과 같습니다.

01

목표 입력

사용자는 결과와 조건만 본사 에이전트에게 전달합니다.

02

업무 분해

본사가 조사, 분석, 생성, 저장 등 필요한 역할로 일을 나눕니다.

03

전문 봇 호출

각 봇은 서로 다른 모델, 스킬, MCP, 플러그인을 사용할 수 있습니다.

04

도구 실행

웹·메일·파일·앱·API·가상 PC에서 실제 작업을 수행합니다.

05

결과 통합

전문 봇들의 결과를 본사가 비교·정리해 하나의 보고로 만듭니다.

06

사람 승인

발송, 거래, 삭제, 공개 등 위험한 행동은 사람이 최종 판단합니다.

과도한 권한
