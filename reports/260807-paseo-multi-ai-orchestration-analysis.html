한 문장 결론

Paseo는 Claude·Codex·Hermes 등 여러 에이전트를 병렬 실행하고, 한 에이전트가 다른 에이전트에 일을 맡기도록 만드는 로컬 퍼스트 오케스트레이션 플랫폼입니다.

도입 가치가 가장 큰 경우는 이미 여러 코딩 에이전트를 쓰면서 터미널·브랜치·작업 상태가 흩어져 있는 개인 개발자와 소규모 팀입니다. 반면 일반 문서 업무 자동화나 전사형 권한·감사 체계가 목적이라면 Paseo만으로는 부족합니다.

What is Paseo?

Paseo는 AI가 아니라
AI 에이전트 관제실입니다

내 컴퓨터에 설치된 Claude Code·Codex·OpenCode·Pi·ACP 에이전트를 Paseo 데몬이 실행하고, 데스크톱·웹·모바일·CLI가 그 데몬에 연결되는 구조입니다.

01

Control Plane

프로젝트·워크스페이스·에이전트·터미널·브라우저·Diff를 한 화면에서 여는 운영 UI입니다.

02

Local Daemon

내 Mac·Windows PC·서버에서 에이전트 프로세스를 시작하고 중지하며 상태와 작업 수명을 관리합니다.

03

Provider Bridge

Paseo가 모델을 대신 제공하지 않고, 이미 설치·로그인된 각 공급자의 CLI와 설정·Skill·MCP를 그대로 사용합니다.

YES
Can Paseo orchestrate multiple AIs?

가능합니다. 교차 공급자 Subagent가 핵심 기능입니다.

Fan-out prompt
이 workspace에 Paseo subagent 3개를 만들어줘.
1번은 요청 처리 경로를 추적하고,
2번은 관련 테스트와 누락된 경계 조건을 찾고,

Hermes Agent도 연결 가능한가?

가능합니다. Hermes Agent는 Paseo의 공식 ACP Provider Catalog에 포함되어 동일 UI에서 실행할 수 있습니다. 다만 Hermes를 메인 Orchestrator로 사용할 때는 선택한 버전과 ACP/MCP 노출 범위에서 Enable Paseo tools가 정상 제공되는지 먼저 확인하고, 초기에는 Hermes를 조사·문서 Worker로 배치해 검증하는 방식이 안전합니다.

First-class Provider는 Paseo가 기능을 깊게 통합한 경로이고, ACP Catalog Provider는 Agent Client Protocol 어댑터로 연결됩니다. 에이전트마다 모델 전환·승인·Subagent 표시 등 세부 기능 범위가 같지는 않을 수 있습니다.
macOS & Windows

설치와 사용 방법을
운영체제별로 구분

Desktop 앱은 데몬을 포함하므로 가장 간단합니다. 공통 전제는 Paseo가 사용할 코딩 에이전트 CLI를 먼저 설치하고 로그인해 두는 것입니다.

macOS 설치

Apple Silicon·Intel DMG 또는 Homebrew Cask 지원

1
사용할 Agent CLI 설치·인증예: Codex CLI, Claude Code, Hermes Agent 중 최소 하나를 터미널에서 정상 실행
2
Paseo Desktop 설치Homebrew 또는 공식 DMG로 설치하면 앱 실행 시 로컬 데몬이 자동 시작

WSL에 대한 판단

Paseo 자체는 Windows 네이티브 빌드를 제공합니다. 다만 연결할 개별 Agent CLI·빌드 도구가 Windows를 완전히 지원하지 않으면 WSL 또는 별도 Linux Dev Box를 실행 Host로 쓰는 편이 안정적일 수 있습니다.

Security & Limits

로컬 퍼스트지만,
자동으로 안전한 것은 아닙니다

Paseo가 코드를 중앙 서버로 프록시하지 않는다는 점과, 에이전트가 내 사용자 권한으로 파일·터미널·자격 증명에 접근할 수 있다는 점을 동시에 봐야 합니다.

강점

데이터 통제

  • 에이전트 프로세스는 사용자가 정한 Mac·PC·VPS에서 실행
  • Paseo가 Provider API 키를 별도 보관·전송하지 않음
  • 모바일 Relay 트래픽은 종단간 암호화
  • 코드 Telemetry·강제 로그인 없이 오픈소스 운영
주의

운영 위험

  • 각 AI Provider는 원래 정책에 따라 코드·Prompt를 클라우드로 전송할 수 있음
  • Worktree는 Git 충돌 방지이지 OS 보안 Sandbox가 아님
  • Pairing QR·링크는 비밀번호처럼 취급해야 함
  • 네트워크 직접 공개 시 비밀번호·VPN·HTTPS 구성 필요
제한

기업 도입 시

  • Hub는 현재 Private Beta이며 더 강한 권한·Sandbox가 로드맵
  • 공급자별 승인·모드·세부 기능이 동일하지 않음
  • Agent가 접근 가능한 Repo·환경 변수·Credential 범위를 별도 통제해야 함
  • 안정판이라도 빠른 업데이트 주기로 회귀 검증 필요
1
모바일은 Relay 우선포트 개방 없이 E2E 암호화 Pairing을 사용하고 QR·Offer URL을 외부에 공유하지 않기
2
0.0.0.0 무인증 금지LAN·VPN 주소에 Bind할 때 Password를 설정하고, 공용망에서는 Reverse Proxy HTTPS 적용
3
최소 권한 실행 계정업무용 저장소만 접근 가능한 별도 사용자·Dev Box·Container를 고려하고 Credential 범위 축소
4
Worktree + 승인 모드독립 편집은 Worktree로 분리하고, 익숙하지 않은 명령은 Allow once·Plan mode부터 시작
5
Stable 우선업무 환경은 안정판을 기본으로 하고 Beta는 별도 Host·Repo에서 기능 검증 후 도입
6
Provider 정책 확인Paseo 보안과 별개로 OpenAI·Anthropic·기타 Provider의 데이터 보존·학습·기업 정책 검토
한국어 음성 사용: 기본 로컬 STT 모델은 영어 전용이고, 다국어 로컬 모델도 공식 문서상 유럽 25개 언어 중심으로 한국어가 포함되지 않습니다. 한국어 Dictation이 중요하면 OpenAI STT Provider 사용 또는 별도 입력 방식을 검토해야 합니다.
Adoption Decision

도입은 “전사 적용”보다
작은 Pilot부터

Paseo의 가치는 에이전트 수가 늘고 병렬 작업이 복잡해질수록 커집니다. 처음부터 많은 Provider를 연결하기보다 한 저장소에서 2개 역할을 분리해 생산성과 안전성을 검증하는 것이 좋습니다.

01

사용 목적 확인

“여러 코딩 Agent의 병렬 개발과 감독”이 핵심인지, 일반 업무 자동화가 핵심인지 먼저 구분합니다.

02

Provider 2개만 시작

계획·구현 또는 구현·리뷰처럼 역할이 명확한 두 Agent만 연결해 품질 차이를 측정합니다.

03

Worktree 표준화

paseo.json의 setup·test·service 명령을 정리해 어느 OS에서도 동일한 작업 환경을 재현합니다.

04

비용·권한 분리

Paseo 비용은 0원이지만 각 Provider 구독·API 비용과 실행 Host·보안 운영 비용은 별도 관리합니다.

권장 4주 Pilot

개인 → 병렬 개발 → 원격 운영 → 팀 통제 순서
WEEK 1

단일 Host 검증

Mac 또는 Windows 한 대에 안정판 설치, Provider 1~2개 연결, PATH와 기본 Prompt 확인

WEEK 2

Worktree 분업

작은 기능을 구현 Agent와 Reviewer로 분리하고 Diff·테스트·Merge 흐름 측정

WEEK 3

모바일·자동화

E2E Relay Pairing, Schedule·Heartbeat로 CI 감시와 일일 Triaging 시험

WEEK 4

운영 기준 확정

허용 Provider, 승인 수준, Repo 접근 범위, 비용 상한, 로그·업데이트 절차 문서화

사용 환경판단이유권장 방식
개인 개발자·1인 창업도입 추천여러 Agent·프로젝트·모바일 감독의 효율이 즉시 체감될 가능성Stable Desktop + 2 Provider + Worktree
2~10명 개발팀통제된 Pilot분업·리뷰 자동화 가치가 크지만 Repo 권한·비용·표준 Script 합의 필요팀 공용 Dev Box보다 개인 Host Pilot부터
대기업·규제 산업보안 검증 후Hub·RBAC·Sandbox·감사 요구를 현재 기능만으로 충족하기 어려울 수 있음격리된 PoC, 보안 심사, Provider Enterprise 정책 병행
비개발 업무 자동화주력 도구 아님메일·CRM·보고서 자동화보다 Coding Agent 실행과 Git 흐름에 초점Hermes·n8n·업무형 Agent 플랫폼을 별도 검토

최종 판단: 개발자용 멀티 에이전트 관제 도구로는 매우 유망

Paseo는 여러 AI 모델의 답을 단순 비교하는 앱이 아니라, 로컬 개발 환경과 Git Worktree 위에서 Agent를 실제로 병렬 실행하고 서로 위임시키는 운영층입니다. Mac과 Windows 모두 공식 지원하지만, 성공적인 도입 여부는 Provider CLI의 안정성, PATH·Shell 구성, Repository 격리와 승인 정책에 달려 있습니다.
