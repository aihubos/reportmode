EXECUTIVE SUMMARY

처음부터 완전 무인으로 돌리지 말고, 승인형 자동화로 시작하세요

Hermes는 웹 검색, 브라우저 조작, 파일·터미널 작업, 이미지 생성, MCP 연결, 예약 작업을 조합할 수 있습니다. 다만 Instagram과 블로그 게시 권한은 각 플랫폼의 인증·API 조건을 충족한 별도 연결이 필요합니다.12

한 문장 결론

Hermes가 초안·검증·예약·기록을 자동화하고, 사람은 사실·브랜드·법적 위험을 최종 승인하는 구조가 비전공자 조직에 가장 현실적입니다. WordPress 또는 Blogger처럼 공식 글쓰기 API가 있는 블로그와 Instagram 프로페셔널 계정을 연결하면 안정적인 시작점이 됩니다.

01

Hermes가 잘하는 일

자료 조사, 장문 원고 작성, 캐러셀 문구 변환, 이미지 생성 요청, 체크리스트 검수, 예약 실행, 결과 파일 기록을 하나의 절차로 묶습니다.

02

별도 연결이 필요한 일

Instagram 토큰, WordPress 애플리케이션 비밀번호, Blogger OAuth 같은 게시 권한은 플랫폼별로 발급하고 Hermes에는 최소 권한만 전달해야 합니다.

03

첫 번째 다음 행동

한 브랜드·한 블로그·한 Instagram 계정에서 2주 동안 “초안만 자동 생성”한 뒤, 승인형 게시로 한 단계 올리는 것이 안전합니다.

AUTOMATION LEVELS

자동화 수준을 세 단계로 나누면, 어디까지 맡길지 명확해집니다

업무 위험이 높을수록 게시 권한을 뒤로 미룹니다. 처음에는 Hermes가 결과물을 만들고, 사람이 확인한 뒤 플랫폼이 게시하도록 역할을 분리합니다.

설정의 핵심은 “Hermes에게 모든 권한을 주는 것”이 아니라, 필요한 기능만 연결하고 게시 전후의 책임자를 분명히 하는 것입니다. Hermes는 비밀값을 ~/.hermes/.env에 보관하도록 안내합니다.4

Hermes + 모델

Hermes 설치와 LLM 제공자 설정이 완료되어야 합니다. 웹·이미지·브라우저·cron 도구는 사용 환경에 맞게 켭니다.

사실 원본

가격, 일정, 제품 특징, 후기 사용 허가, 링크 등 “AI가 추측하면 안 되는 항목”을 한 파일에 모읍니다.

게시 계정

Instagram은 비즈니스 또는 크리에이터 프로페셔널 계정이 필요합니다. 개인 계정은 공식 관리 API 대상이 아닙니다.5

공식 커넥터

Instagram API, WordPress REST API, Blogger API처럼 지원 범위가 명확한 연결을 우선합니다.

승인 담당자

누가 무엇을 확인하고 “게시 승인”을 내리는지 정합니다. 대표자·마케팅 담당자·법무 검토를 상황별로 구분합니다.

게시 로그

승인자, 게시 시간, 플랫폼 ID, URL, 원본 버전, 실패 메시지를 남겨야 중복 게시와 책임 불명확을 막을 수 있습니다.

OFFICIAL API PATH

Instagram

프로페셔널 계정의 이미지·영상·릴스·캐러셀 게시를 공식 API로 연결하는 방식입니다. 앱 심사와 토큰 관리가 필요합니다.6

자동화 적합도 · 높음단, 초기 개발자 설정 난도가 가장 높습니다.
1
프로페셔널 계정 준비

비즈니스 또는 크리에이터 계정을 사용합니다. Instagram Login 방식은 Facebook Page 연결 없이도 사용할 수 있습니다.

2
Meta 앱·권한·심사

로그인 흐름과 콘텐츠 게시 권한을 구성합니다. 공식 시작 문서는 App Review가 필요하다고 안내합니다.7

3
미디어 공개 URL 준비

Meta가 파일을 가져갈 수 있도록 게시 시점에 접근 가능한 URL을 제공합니다. 이미지 게시의 공식 문서상 지원 형식은 JPEG입니다.6

4
컨테이너 생성 → 상태 확인 → 게시

/media로 컨테이너를 만들고 처리 상태를 확인한 뒤 /media_publish를 호출합니다.

5
게시 한도 사전 확인

공식 문서는 계정당 이동 24시간 동안 API 게시 100개 한도를 안내합니다. 실무에서는 훨씬 낮은 자체 한도를 둡니다.6

가이드 판단: 브라우저 클릭 자동화보다 공식 API를 우선하고, 계정 전환·권한 심사 기간을 파일럿 일정에 포함하세요.
BEST FOR APPROVAL FLOW

WordPress

게시물을 draft, future, publish 상태로 만들 수 있어 승인형 자동화에 가장 유연합니다.8

자동화 적합도 · 매우 높음콘텐츠 소유권과 운영 통제가 중요한 조직에 적합합니다.
1
HTTPS 사이트 준비

REST API가 활성화된 WordPress 사이트를 사용합니다.

2
전용 사용자 생성

관리자 전체 권한 대신 게시에 필요한 최소 역할의 계정을 따로 만듭니다.

3
Application Password 발급

WordPress 5.6 이상에서는 사용자 편집 화면에서 애플리케이션 비밀번호를 만들고 HTTPS Basic Auth로 전달할 수 있습니다.9

4
초안부터 테스트

POST /wp/v2/posts 요청에 제목·본문·상태를 보내되 첫 테스트는 반드시 draft로 실행합니다.

5
URL과 Post ID 기록

응답으로 받은 ID와 링크를 게시 로그에 저장하고, 같은 콘텐츠가 다시 게시되지 않도록 확인합니다.

권장: WordPress에는 Hermes가 직접 공개 게시하지 않고 “초안 생성 → 사람이 미리보기 → 예약 승인” 순서로 연결하세요.
SIMPLE OFFICIAL API

Google Blogger

Blogger API의 posts.insert 메서드로 제목과 HTML 본문을 게시할 수 있습니다. 쓰기 작업에는 OAuth 인증이 필요합니다.10

자동화 적합도 · 높음단순한 개인·프로젝트 블로그에 적합합니다.
1
Google Cloud 프로젝트

Blogger API를 활성화하고 OAuth 동의 화면을 구성합니다.

2
OAuth 토큰 발급

블로그 쓰기 범위를 요청하되 토큰은 Hermes 프롬프트가 아니라 비밀 저장소에 둡니다.

3
Blog ID 확인

게시 대상 블로그 ID를 설정 파일에 고정합니다.

4
HTML 본문 생성

Hermes가 제목, 본문, 링크, 이미지 대체 텍스트를 만들고 API용 JSON으로 변환합니다.

5
응답 URL 검증

게시 후 반환된 URL이 열리는지 확인하고 로그에 남깁니다.

주의: Google OAuth 토큰 갱신과 동의 화면 상태를 주기적으로 점검해야 예약 작업이 중단되지 않습니다.
SEMI-AUTOMATION

네이버 블로그

현재 공개 Open API 목록에는 블로그 검색과 공유 기능은 보이지만, WordPress처럼 블로그 글 생성용 공개 REST 엔드포인트는 확인되지 않습니다.11

자동화 적합도 · 제한적보고서의 판단: 초안 자동화 + 사람 발행을 기본으로 봅니다.
1
Hermes가 초안 패키지 생성

제목, 본문, 소제목, 이미지 순서, 태그, 대표 이미지 문구를 한 폴더에 저장합니다.

2
클립보드·파일 전달

사람이 네이버 에디터에 붙여넣기 쉬운 HTML이 아닌 일반 텍스트와 이미지 파일로 준비합니다.

3
사람이 최종 발행

미리보기, 스마트에디터 서식, 링크, 대표 이미지, 카테고리를 직접 확인합니다.

4
브라우저 자동화는 보조

Hermes의 브라우저 도구로 폼 입력을 도울 수 있지만, UI 변경·로그인·CAPTCHA에 취약하므로 사람이 보고 있는 세션에서만 사용합니다.12

5
게시 URL 되돌려 기록

발행 후 URL을 Hermes에 전달해 콘텐츠 로그와 재사용 자료를 갱신합니다.

미확인 범위: 네이버의 파트너·제휴 전용 기능은 공개 문서에서 확인되지 않았으므로 별도 계약이 있다면 해당 약관을 우선합니다.
~/.hermes/.env · 예시 구조
# 실제 키는 문서·프롬프트·Git에 넣지 않습니다.
INSTAGRAM_ACCOUNT_ID=your_professional_account_id
INSTAGRAM_ACCESS_TOKEN=***

WORDPRESS_BASE_URL=https://example.com
WORDPRESS_USER=hermes-publisher
WORDPRESS_APP_PASSWORD=***

BLOGGER_BLOG_ID=your_blog_id
GOOGLE_OAUTH_TOKEN_PATH=/secure/path/token.json

COPY-READY PROMPTS

Hermes에는 “무엇을 만들지”보다 “어디까지 허용할지”까지 말하세요

예약 작업은 기존 대화의 맥락을 기억하지 않는 새 세션으로 실행됩니다. 원본 위치, 출력 형식, 금지 조건, 승인 규칙을 프롬프트 안에 완결된 형태로 넣습니다.2

1 · 주간 콘텐츠 패키지

초안만 생성하기

첫 파일럿에서는 게시 권한 없이 결과물 품질부터 검증합니다.

/content-ops/brand-guide.md와 이번 주 content_brief.yaml을 읽고 콘텐츠 패키지를 만들어줘.

1. 공식 원본과 제공 파일만 사실 근거로 사용
2. 블로그 원고 1편: 제목, 요약, 본문, CTA, 메타 설명
3. Instagram 캐러셀 6장: 장별 문구, 캡션, 대체 텍스트, 해시태그
4. facts_check.md에 사실·해석·미확인을 구분
5. 개인정보, 과장, 보장 표현, 출처 없는 수치가 있으면 FAIL 표시
6. /content-ops/output/YYYY-MM-DD-topic/에 저장

중요: 플랫폼에 게시하거나 토큰을 사용하지 말고, 마지막에 검토가 필요한 항목만 요약해줘.
2 · 승인 전 검수

빨간불만 찾기

문장 다듬기보다 잘못 게시될 가능성을 먼저 찾습니다.

지정한 콘텐츠 폴더를 게시 전 검수해줘.

검수 기준:
- 가격, 날짜, 장소, 제품 사양이 원본과 일치하는가
- “최고, 1위, 완치, 보장” 등 증명되지 않은 표현이 있는가
- 고객 이름, 얼굴, 연락처 등 개인정보 사용 허가가 있는가
- 이미지와 문구의 저작권·사용 범위가 기록되어 있는가
- 블로그 링크와 Instagram CTA가 실제로 열리는가
- 동일 콘텐츠의 중복 게시 기록이 없는가

결과를 PASS / NEEDS_EDIT / BLOCKED로 표시하고, 원문을 임의로 수정하지 말고 수정 제안만 작성해줘.
3 · 승인 후 발행

승인된 파일만 게시하기

승인 파일과 게시 로그가 없으면 작업을 중단하도록 지시합니다.

/content-ops/queue/에서 APPROVED.json이 있는 항목만 처리해줘.

발행 순서:
1. 승인자, 승인 시간, 승인된 파일 해시를 확인
2. WordPress는 먼저 future 상태로 예약하고 반환된 Post ID와 URL 기록
3. Instagram은 승인된 JPEG/영상 URL만 사용해 컨테이너 생성
4. 처리 상태가 FINISHED인 경우에만 media_publish 실행
5. publish_log.jsonl에 플랫폼, ID, URL, 시간, 원본 버전 기록
6. 같은 content_id가 이미 성공 기록에 있으면 다시 게시하지 않음
7. 오류가 나면 재시도 1회 후 중단하고 승인자에게 오류 요약 전달

APPROVED.json이 없거나 facts_check가 PASS가 아니면 게시하지 말고 [BLOCKED]로 종료해줘.

추천 폴더 구조

content-ops/
├── brand-guide.md       브랜드 톤·금지어
├── sources/             공식 원본·사진 권리
├── briefs/              주제별 입력 브리프
├── output/              Hermes 생성 결과
├── queue/               승인 대기·승인 파일
├── published/           최종 게시본
└── logs/
    ├── publish_log.jsonl
    └── error_log.jsonl

원본, AI 생성물, 승인본, 게시본을 한 폴더에 섞지 않는 것이 가장 단순한 사고 예방 장치입니다.

주간 초안 cron 예시

Hermes CLI · 초안만 생성예약 작업
hermes cron create "every Mon at 09:00" \
  "Read /Users/me/content-ops/briefs/weekly.yaml and /Users/me/content-ops/brand-guide.md. Create one blog draft and one Instagram package. Save under /Users/me/content-ops/output/. Do not publish. Return only the review checklist and output path." \
  --workdir /Users/me/content-ops \
  --deliver telegram \
  --name "weekly-content-draft"

Hermes cron은 새 세션에서 실행되며, 지정한 workdir의 파일과 규칙을 사용하도록 설정할 수 있습니다. 자동 게시용 cron은 승인 구조가 충분히 검증된 뒤 별도로 만드세요.2

RISKS & GUARDRAILS

자동화 실패는 글쓰기 오류보다 권한·중복·과장 표현에서 더 크게 발생합니다

Hermes는 위험한 명령 승인, 파일 쓰기 안전, 컨테이너 격리, MCP 자격 증명 필터링 같은 보안 계층을 제공하지만, 게시 콘텐츠의 사실성과 계정 운영 책임까지 자동으로 대신하지는 않습니다.13

×
“Hermes가 알아서 사실을 확인하고 게시한다.”
원본이 없거나 출처가 모호하면 자연스러운 문장으로 잘못 채울 수 있습니다.
✓
사실 원본과 검수표를 분리합니다.
가격·날짜·효능·수치에는 근거 파일을 연결하고 미확인은 게시 차단 조건으로 둡니다.
×
“토큰을 프롬프트에 붙여 넣으면 편하다.”
대화 기록, 로그, 스크린샷을 통해 비밀값이 노출될 수 있습니다.
✓
비밀값은 .env와 최소 권한 계정에 둡니다.
프롬프트에는 환경변수 이름만 쓰고 토큰은 정기 교체합니다.
×
“실패하면 성공할 때까지 계속 재시도한다.”
중복 게시, API 한도 소진, 잘못된 캡션 반복으로 이어질 수 있습니다.
✓
콘텐츠 ID와 성공 로그를 먼저 확인합니다.
재시도는 제한하고, 상태가 불명확하면 중단 후 사람에게 알립니다.
×
“브라우저 자동화면 모든 블로그에서 완전 자동이 가능하다.”
로그인, CAPTCHA, UI 변경, 서비스 정책 때문에 안정성이 떨어집니다.
✓
공식 API를 우선하고 브라우저는 보조로 씁니다.
API가 없는 플랫폼에서는 초안 자동화와 사람이 보는 세션의 폼 입력까지만 권장합니다.
×
“블로그 글을 그대로 Instagram에 줄이면 된다.”
채널의 읽기 방식과 시각적 구조가 달라 반응이 떨어지고 반복 콘텐츠처럼 보입니다.
✓
핵심 사실만 공유하고 형식은 다시 설계합니다.
블로그는 설명과 검색, Instagram은 훅·시각·저장 가치를 중심으로 만듭니다.
반드시 사람 검토: 의료·법률·금융 조언, 효능·성과 보장, 할인 조건, 고객 후기, 제3자 얼굴·이름, 저작권이 불명확한 이미지, 대외 공지와 위기 대응 문구는 자동 게시 대상에서 제외하세요.
4-WEEK PILOT

4주 동안 “글의 개수”보다 오류 없는 반복 가능성을 검증하세요

파일럿의 목표는 AI가 멋진 문장을 쓰는지보다, 같은 입력 규칙과 승인 절차로 안전하게 반복할 수 있는지 확인하는 것입니다.

4주 실행 계획

1
1주차 · 기준과 계정

브랜드 가이드, 원본 템플릿, 승인자, WordPress/Blogger 또는 Instagram 테스트 계정을 준비합니다.

2
2주차 · 초안 자동화

게시 없이 블로그 2편과 Instagram 패키지 2개를 만들고 수정 유형을 기록합니다.

3
3주차 · 승인형 게시

승인된 1~2개 콘텐츠만 공식 API로 예약·게시하고 ID·URL·오류를 검증합니다.

4
4주차 · 운영 판단

시간 절감, 수정 빈도, 게시 성공, 오류 대응을 보고 확대·유지·중단을 결정합니다.

파일럿 성공 기준 예시

중대한 오류 0건잘못된 가격·날짜·링크·개인정보·중복 게시가 없어야 합니다.
모든 게시에 근거와 승인 기록출처 파일, 승인자, 게시 ID, URL이 한 로그에서 연결되어야 합니다.
사람의 수정 유형이 반복 가능같은 수정이 반복되면 브랜드 가이드나 Skill에 규칙으로 반영합니다.
실패 시 자동 중단인증 만료·미디어 오류·상태 불명확 시 무한 재시도하지 않고 알림이 와야 합니다.
채널별 결과가 다르게 읽힘블로그는 검색·설명, Instagram은 시각·저장·공유 목적에 맞아야 합니다.
