ROLLBACK & UNINSTALL

문제가 생기면 삭제보다 먼저 원래 Codex로 되돌립니다

OpenCodex의 Codex 설정 주입은 가역적으로 설계되어 있습니다. restore는 프록시를 유지한 채 원래 Codex로 전환하고, stop은 프록시를 중지하면서 원래 설정을 복원합니다.34

1

2
OpenCodex로 다시 전환

ocx restore back · 실행 중인 프록시를 다시 연결

3
프록시 중지 + 원복

ocx stop · service도 함께 멈추고 native Codex 복원

4
서비스만 제거

ocx service uninstall 또는 ocx codex-shim uninstall

RISKS & RECOMMENDATION

“로컬·오픈소스·호환”이라는 단어만으로 안전성을 판단하지 않습니다

프로젝트는 MIT 라이선스의 독립 커뮤니티 소프트웨어이며, 보안 수정은 최신 npm 릴리스와 main을 대상으로 best-effort로 제공됩니다. 최신 버전을 유지하고 프로바이더 약관·조직 보안정책을 함께 적용해야 합니다.912

×“프록시가 로컬이므로 코드가 외부로 나가지 않는다.”
✓프록시는 로컬이지만 요청은 선택한 업스트림으로 갑니다. 데이터 보존·학습·지역 정책은 해당 프로바이더 기준입니다.
×“모델 목록에 보이면 바로 쓸 수 있다.”
✓목록은 라우팅 가능성을 보여줄 뿐, 계정 접근 권한·요금제·지역 제한을 부여하지 않습니다.
×“OpenAI 호환 API면 모든 Codex 기능이 동일하다.”
✓tool call, reasoning effort, vision, context, streaming semantics는 모델·adapter마다 달라 실제 과제로 검증해야 합니다.
×“여러 계정을 묶으면 사용 한도를 자유롭게 우회할 수 있다.”
✓계정 pooling 기능이 있더라도 요금·쿼터 회피에 사용하지 말고 각 서비스 약관과 조직 정책 안에서만 운영합니다.
×“config.json에 키를 넣고 Git으로 동기화해도 된다.”
✓ENV 참조를 우선하고 literal 키·OAuth 파일·로그·백업을 Git과 공유 저장소에서 제외합니다.
