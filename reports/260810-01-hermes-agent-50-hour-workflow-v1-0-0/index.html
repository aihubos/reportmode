SEVEN OPERATING LESSONS

Hermes를 오래 쓰면 결국
프롬프트보다 운영 규칙을 고치게 됩니다

제가 영상에서 가장 많이 본 장면은 성공 화면이 아니었습니다. 검색 기간을 바꾸고, 오탐을 고치고, 거절 기준을 수정하고, 크론 주기를 다시 잡는 장면이었습니다. 에이전트는 한 번에 완성하는 제품보다 계속 조정하는 운영체제에 가깝습니다.

01

불편이 큰 한 가지부터 시작합니다

메일 전체를 자동화하지 말고, “광고 문의를 놓친다”처럼 반복되고 손실이 분명한 문제를 고릅니다. 자동화의 가치는 기능 수가 아니라 줄어든 마찰에서 나옵니다.

02

읽기·정리·초안·발송을 분리합니다

같은 워크플로 안에 있어도 권한은 단계별로 나눕니다. 읽기와 분류는 자동, 초안은 자동, 발송은 승인. 이 한 줄만 지켜도 사고 범위가 크게 줄어듭니다.

03

사실은 Memory, 절차는 Skill에 둡니다

“성과형 광고를 선호하지 않는다”는 사용자 사실입니다. “브랜드 조사→조건 비교→영문 초안→한글 요약”은 재사용 절차입니다. 둘을 섞으면 메모리는 비대해지고 스킬은 맥락을 잃습니다. [출처 3] [출처 4]

04

Cron 프롬프트는 혼자서 완결돼야 합니다

Hermes 크론은 fresh agent session에서 실행됩니다. “아까 말한 기준대로”가 아니라 검색 범위·대상 시트·중복 기준·전달 채널을 모두 적어야 합니다. [출처 5]

최근 24시간 · 중복 ID · Draft only
05

드라이런과 로그가 자동화의 절반입니다

새 행이 0건이라고 했는데 실제 메일이 더 있었던 장면처럼, 에이전트는 그럴듯하게 놓칠 수 있습니다. 검색 쿼리·실행 시각·처리 건수·오류를 남기고 샘플을 사람이 대조해야 합니다.

06

Self-improvement에도 승인 게이트를 둡니다

Hermes는 스킬을 스스로 만들고 수정할 수 있습니다. 현재 문서상 기본은 자유 쓰기이지만, 보안 환경에서는 skills.write_approval: true로 모든 변경을 검토할 수 있습니다. [출처 4]

07

Curator는 마법의 기억 청소부가 아니라 스킬 정리 담당입니다

공식 문서 기준 Curator는 사용 빈도를 추적하고 오래 쓰지 않은 스킬을 active→stale→archived 상태로 옮깁니다. 기본 확인 조건은 마지막 실행 후 7일, 최소 idle 2시간이며 자동 삭제는 하지 않습니다. 영상 설명처럼 “메모리 전체를 알아서 정리한다”고 이해하면 운영 범위를 과대평가할 수 있습니다. [출처 6]

FACT-CHECK & CORRECTION

영상에서 그대로 따라 하기 전에
네 가지는 꼭 수정해야 합니다

×권한 창이 뜨면 Always Allow를 누른다
✓읽기부터 시작하고, 쓰기·발송·터미널 명령은 필요한 범위에서 매번 또는 규칙별로 승인합니다. [출처 7]
×OAuth client JSON을 Slack 스레드에 첨부한다
✓채팅 업로드 대신 SSH/SCP, 암호화된 secret store, 제한된 로컬 경로를 사용합니다. 자격증명 파일과 refresh token은 비밀정보입니다. [출처 8] [출처 9]
×Curator가 메모리와 스킬을 모두 알아서 청소한다
✓현재 공식 문서에서 Curator의 직접 관리 대상은 스킬 라이브러리입니다. 일반 사용자 메모리는 별도로 검토해야 합니다. [출처 6]
×PlayMCP가 Hermes를 공식 지원한다
✓영상에서는 연결 성공 사례가 나오지만, 카카오 공식 발표가 명시한 에이전트는 OpenClaw입니다. Hermes는 사용자 테스트 호환으로 표현해야 합니다. [출처 10]

FAQ

Hermes를 처음 붙일 때 가장 많이 생기는 질문

Hermes Agent는 무엇인가요?
Nous Research가 공개한 오픈소스 에이전트로, 메시징 게이트웨이·지속 메모리·스킬·크론·도구 실행을 한 환경에서 운영할 수 있습니다. 단순 챗봇보다 장기 실행과 반복 업무에 초점이 있습니다. [출처 2]
Memory와 Skill은 어떻게 다르나요?
Memory는 사용자 취향·환경·지속 사실처럼 항상 참고할 작은 정보입니다. Skill은 여러 단계의 작업 순서, 도구 사용법, 실패 복구처럼 필요할 때 불러올 절차입니다. [출처 3] [출처 4]
이메일 답장을 완전 자동 발송해도 될까요?
초기에는 권하지 않습니다. 분류 오류, 잘못된 가격, 번역 오해, 수신자 혼동이 평판과 계약에 직접 영향을 줍니다. draft까지 자동화하고 사람이 발송하는 구조가 안전합니다.
Cron 작업이 현재 대화를 기억하나요?
현재 공식 문서 기준 크론은 fresh agent session에서 실행됩니다. 따라서 “앞서 말한 기준”에 기대지 말고 검색 범위, 파일 위치, 중복 기준, 전달 대상을 프롬프트 안에 모두 적어야 합니다. [출처 5]
Curator가 메모리도 정리하나요?
현재 공식 문서에서 Curator는 스킬 라이브러리 유지관리 기능으로 설명됩니다. 오래 쓰지 않은 스킬을 stale·archived 상태로 옮기지만 자동 삭제하지 않습니다. 사용자 메모리는 별도로 검토해야 합니다. [출처 6]
PlayMCP는 Hermes와 공식 연동되나요?
카카오가 공식 발표한 직접 연동 대상은 OpenClaw입니다. 원자료 영상에서는 Hermes로 연결한 사용자 테스트가 나오지만, 공식 지원과 동일하게 표현하면 안 됩니다. [출처 10]
가장 먼저 자동화할 한 가지는 무엇인가요?
실수 비용은 낮고 반복 빈도는 높은 읽기 업무가 좋습니다. 예를 들어 매일 오는 뉴스레터 3개를 링크와 함께 요약해 Slack DM으로 받는 것부터 시작하면 권한과 검증 부담이 작습니다.
